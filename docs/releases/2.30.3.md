# 2.30.3 — Station tools and display polish 🛠️📺

This patch consolidates the tested station, provisioning and display improvements since 2.30.2. Publication requires the complete signed CI bundle.

## Re-provision compatible devices

Start from Ports, an existing module card or an IPv4 address in CMs. A compatible CM4/Pi 4 can be reset even when it is unrecognized, has no local history or was flashed by an unavailable station. OURS is informational.

The shared wizard checks access, hardware, Ethernet identity, root disk and network boot before a separate erase confirmation. It uses the current primary's active project and image. A secondary opens the explicitly configured current primary; it transfers address hints only. New history appears when the utility OS really starts a run. Changed identity/project, busy station operations and expired checks prevent dispatch; uncertain results are never retried automatically.

The first release supports whole eMMC/SD, MBR and ext4 root partition 2. Existing registered v1 agents remain usable; first-time boards can use a read-only inspector through an authorized account with sudo. Unsupported layouts and stations are refused. [Instructions](https://github.com/nimbo78/cmprovision/blob/v2.30.3/docs/operations.md#re-provision-an-installed-sensor).

## Storage, reports and images

- Settings → System → Storage shows bounded measurements and previews cleanup. Images used by projects, active runs or split preparation are protected.
- Device reports download as self-contained HTML or JSON with bounded diagnostics and embedded report fonts.
- Images can explicitly check GitHub for a newer matching stable image. The application leaves the project and download choice to the operator.
- Saving DHCP reservations restores both data and configuration if applying them fails.

## Displays and recovery

- HDMI shows management uplinks: interface, SSID/signal or Ethernet speed, and addresses.
- Rescue AP respects its configured ten-minute delay; HDMI can show its QR for one minute. The timing is recovered when adopting an already active AP.
- FPMS has an Appearance submenu for Light/Dark/Auto. Appearance, reboot and shutdown have been confirmed on hardware.
- PoE restart is available while power is supplied without an Ethernet link; peer stations retain the neutral cm mark.
- Package upgrades refresh an active shared HDMI/FPMS data reader. Station image recovery initialization is checked during the build.

[Station operations](https://github.com/nimbo78/cmprovision/blob/v2.30.3/docs/station-operations.md), [rescue Wi-Fi](https://github.com/nimbo78/cmprovision/blob/v2.30.3/docs/rescue-wifi.md), [FPMS](https://github.com/nimbo78/cmprovision/blob/v2.30.3/docs/fpms-display.md).

## Validation and remaining hardware acceptance

Universal Re-provision validation after its independent review fixes: 2361 PHP tests / 9276 assertions; 90 JavaScript tests; 8 real OpenSSH tests / 17 assertions. The PHP run retained three existing warnings and 27 environment-dependent skips; the eight SSH cases were run separately. Tailwind 3.4.19 rebuilt the stylesheet.

All four important review findings have regression coverage: account inspection cannot bypass station protection; raw switch forwarding must identify a unique access edge; DHCP claims are checked consistently for both MAC and IP entry; serial-to-MAC conflicts are checked again immediately before dispatch. Registered devices with unavailable boot-order data show an explicit warning; an explicitly unusable boot order is refused.

FPMS Lite is a supported profile for Raspberry Pi OS Lite Trixie arm64 on CM4
with a Waveshare 1.44-inch ST7735 display, including New/Classic and Light/Dark/Auto.
The operator confirmed Classic, correct Auto appearance at the appropriate times,
and connection using the physical FPMS QR on 15 November 2026. The exact instant
of the automatic day/night change was not watched. The station image remains experimental.

Rescue AP coexistence passed on da2 with fd3: a temporary timer activated the AP after image writing began and ended the forced mode after ten minutes. A real d62 Wi-Fi client obtained `192.168.240.16` from the AP, reached the login page twice (HTTP 200), and was refused access to the stand-only module API (HTTP 403). Management stayed on `wlan1`; the flash passed SHA256 and OS check in **7:18**, matching the preceding run without AP. Return to standby was confirmed after 605.6 seconds, with unchanged configuration and all temporary client profiles, timers and runtime files removed. The ordinary fifteen-minute manual-start behavior and the configured ten-minute automatic-search delay are unchanged.

Development packages `2.31.0~dev6` (`2008715`) were installed on d62 followed by da2, preserving their secondary/primary roles and one verified package snapshot per station. Physical fd3 (CM4 rev 1.0) passed both the restricted legacy-key check and the extended account inspector.

The first-time reset was then verified on fd3 after backing up and removing its registration. The extended inspector used the saved WLAN Pi account while no Cm row existed; one erase was dispatched, and genuine network boot created the new record. The complete cycle passed SHA256 and OS check in **7:18**, with OS state `running` and unchanged EEPROM. All **141** previous journal rows were retained; **4** surviving notification references were reattached to the new record.
## Waveshare detection and visual guides

FPMS Lite checks the Waveshare controller before starting display, button or backlight GPIO. Settings shows the detected profile and ID. Without a supported response, the service waits and retries; HyperPixel is not yet a supported profile. The probe restores GPIO state, including pin bias when the kernel cannot report it.

On 16 November, d62 passed a cold PoE start: controller ID `7C89F0` was detected in **8.1 seconds**. On da2 without a GPIO display, both disabled SPI and three probes over **66 seconds** produced no false display detection or button/backlight requests. Original GPIO and service state were restored.

The English and Russian Rescue Wi-Fi guides now include lifecycle and shutdown-timing SVGs. They distinguish the **10-minute** search, consecutive **60 + 60 seconds** of recovery, connected-client retention and the independent **60-second** QR card. All four figures passed desktop/mobile rendering, local-link and policy-derived regeneration checks.

## Development-build transition

Stable 2.30.x stations can update through Settings → Updates. Debian considers the previously tested `2.31.0~dev…` builds newer than 2.30.3. Moving those development stations to this release requires a backed-up manual package installation over SSH; the updater continues to refuse downgrades. Development-version changelog entries and recorded hardware results retain their original numbers.
