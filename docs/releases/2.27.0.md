# 2.27.0 — Station power and complete automatic releases 🔌📦

## What changed

- Restart or shut down the provisioner in **Settings → Status → Station power**.
  The web interface asks for account-password confirmation and then explicit action confirmation.
- Open the same controls with **KEY3 on FPMS Lite**, in Classic/New and Light/Dark/Auto.
  The joystick centre selects; **KEY1 confirms**, **KEY2 cancels**. Cancel is selected initially.
- Unfinished and silent provisioning runs require a **separate interruption warning and confirmation**.
  The server rechecks live runs. Once scheduled, new provisioning starts wait for the station to return.
- The browser confirms a restart only after the station reports a new boot identity.
  A network timeout or malformed response remains uncertain.
- A new stable version merged into `main` now starts the complete release chain after successful checks:
  production packages, ARM64 station image, artifact audits, upload and verified publication.
  Development versions remain unpublished; existing tags and release files are never replaced.

## Verification and operational limits

The release workflow runs PHP, JavaScript, FPMS and release-guard tests, builds clean production packages,
audits the image and checks the uploaded file set and SHA-256 hashes before publication.
Detailed results are retained in the producing GitHub Actions run.

Power actions begin about five seconds after final confirmation and cannot then be cancelled.
Interrupting an image or EEPROM write may require board recovery. After shutdown,
cycle **PoE or external power** to start the station again.

The image remains **experimental**, and FPMS remains **preview**. Physical KEY1/KEY3,
actual reboot/shutdown and power-cycle recovery still require hardware acceptance;
automated publication does not claim these checks were performed.
No database migration is required. The retained full WLAN Pi OS adapter has no power controls.
