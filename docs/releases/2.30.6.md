# 2.30.6 — Recovering an interrupted station update 🔌

## When power returns

During an update, the station stores which boot services were running. At the next power-on, DHCP/TFTP and USB boot wait for the updater to finish recovery. A primary can then serve boards again. A secondary keeps its masked services. This protection applies to operations started by the 2.30.6 updater.

## Before installing

**Settings → Updates → Review and apply** shows required and available space on each filesystem. A shortfall leaves the stand available for provisioning. Before a rollback, the updater also checks the selected snapshot, archive contents, package versions and station role. The application snapshot still covers uploaded images. [Recovery and space requirements](https://github.com/nimbo78/cmprovision/blob/v2.30.6/docs/updates.md)

## Reading the journal

A manual rollback also checks whether the optional FPMS display package was present in the snapshot. If the display package or the station role has changed, the station shows the mismatch while it is still online.

After installation the page refreshes the installed version and removes the completed offer. If a later publisher check fails, the journal shows the error and the time of the last successful check.

## Power-cut test

We disconnected PoE from the secondary station for eight seconds while the update worker had paused services to activate the already selected Utility OS. On cold boot, the station restored that selection, reopened the web interface and queues, and started FPMS. DHCP/TFTP and USB boot stayed masked. Separate Debian tests cover package installation and application rollback.

On an existing station, choose **Settings → Updates → Application**. For a new station, write the ARM64 Lite image from the release assets. [Installation guide](https://github.com/nimbo78/cmprovision/blob/v2.30.6/docs/upgrading.md)
