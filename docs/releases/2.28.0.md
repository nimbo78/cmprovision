# 2.28.0 — Station time and System settings 🕒✨

## What changed

- **Settings → System** groups the provisioner's time, power, HDMI, FPMS and Backup controls. Services and journals remain on **Status**; existing links to moved sections continue to work.
- Search installed time zones, enable or disable NTP, configure up to eight servers or return to system defaults. The page shows local time, UTC, synchronization state and the selected server.
- Time settings require password confirmation and an idle station. The fixed privileged controller validates requests and restores the previous managed configuration and service state if application fails.
- Web, HDMI and FPMS follow the system time zone, including cached application configuration and running display publishers. An explicit valid `APP_DISPLAY_TIMEZONE` override remains supported. Records and API timestamps remain UTC.
- New full system snapshots record managed NTP configuration presence and the supported service state. Data-only backups and selective transfer do not change another station's time settings.

## Verification and limits

The full local PHP suite passed **2178 tests with 8573 assertions**; 27 tests were skipped and three existing warnings remained. All **85 JavaScript** and **136 Python helper tests** passed. The development PR's final CI passed all six required jobs, including real Debian installation, automatic package rollback and interrupted-install recovery. Browser checks covered password confirmation, keyboard submission, validation, draft preservation, old section links and light/dark layouts at desktop and mobile widths. Independent review and follow-up verification completed.

The NTP editor supports an existing **systemd-timesyncd** installation. It reports unsupported or masked providers without replacing them. Saving settings confirms application, not successful synchronization with an unreachable server. Interface-provided NTP servers can still participate; inspect the effective server lists. See [station time and synchronization](../system-time.md).

Install through **Settings → Updates** on an idle station. Matching FPMS Lite is updated when installed; the selected Utility OS and prior service states are preserved. No database migration is added. The release workflow builds and audits both packages and the ARM64 image, signs update metadata and verifies uploaded hashes before publication.

Hardware mutation acceptance follows publication, first on wlanpi-d62 and then wlanpi-da2. Read-only status collection was verified on both stations before release. The station image remains **experimental** and FPMS remains **preview**.
