# 2.30.7 — Re-provision without a DHCP lease and stable Wi-Fi names

## Re-provision after a station handover

Enter the sensor's current IPv4 address when the new primary has no DHCP lease for it. The station checks for a reachable neighbor with the expected address and MAC on the provisioning interface. A neighbor on a different interface is ignored. The access check was verified on the bench using an existing sensor and an empty lease file.

## Wi-Fi names in the ARM64 station image

On a CM4 with the onboard Broadcom SDIO radio, the image assigns it `wlan0` before NetworkManager starts. A single additional radio gets `wlan1`. Linux assigns the names on systems without the onboard radio or with several additional radios. The image service was tested on a CM4 booting from eMMC after a PoE power cycle. The Intel card provided management access while the onboard card hosted the rescue access point. [Station setup](https://github.com/nimbo78/cmprovision/blob/v2.30.7/docs/station-setup.md)

Install the application update from **Settings → Updates → Application** to get the Re-provision fix. Use the published ARM64 station image to install the Wi-Fi naming rule on a new station.
