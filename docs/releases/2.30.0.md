# 2.30.0 — Know your CM4 and keep a way back in 🧩📡

## What changed

- **Device details in web, HDMI and Classic/New FPMS** show the Compute Module model, PCB revision, RAM, eMMC capacity, built-in Wi-Fi and inferred CM4 SKU. The compact hardware block uses the existing card font. Unknown attributes stay unknown; a Lite module and a missing eMMC remain distinct. The SKU is an inference from factory attributes, not a verified supplier part number.
- **Settings → Network → Rescue Wi-Fi** can start a protected access point after saved management networks remain unavailable for **10 minutes**. The feature is off on fresh installations. It requires two independent radios, an AP-capable spare radio and provisioning DHCP already bound to the stand interface. A healthy client connection is preserved.
- **Engineers can reach the station and sensors through the AP:** NetworkManager supplies DHCP/DNS/NAT for web, SSH, routed sensors, reachable VLANs and an available upstream. Sensors do not need an additional return route. The AP uses a nonoverlapping private subnet; it does not relay layer-2 boot/discovery traffic or reconfigure flashing Ethernet/VLANs.
- **Recovery respects connected engineers.** Once management has been stable for 60 seconds, the AP stays up while clients remain, then stops after 60 seconds without clients. Manual start/pause, staged configuration and a separate disconnection confirmation protect active sessions. A confirmed external AP shutdown also removes its owned source-guard rule.
- **Consistent status and private credentials:** web, HDMI and both FPMS layouts show AP state and address separately from internet connectivity. Passwords are excluded from ordinary status snapshots and displays; showing the AP password requires web password confirmation.
- **Encrypted full backups** include rescue configuration and its NetworkManager profile as network settings. Migration preserves destination networking by default; explicit restoration supports permanent-MAC radio mapping. The isolated CI container now includes `sysctl` for real DHCP/NAT acceptance.

## Verification and limits

Feature validation in [PR #22](https://github.com/nimbo78/cmprovision/pull/22) and [PR #23](https://github.com/nimbo78/cmprovision/pull/23) passed **2232 PHP tests / 8800 assertions**, **89 JavaScript tests**, **72 root/network tests**, **66 HDMI tests** and **380 FPMS tests**. The PHP run retained three warnings and 27 opt-in environment-dependent skips. CI also passed disposable Debian update/rollback and full-restore acceptance, real loopback backup storage, FPMS packaging and Utility OS build/checks. Release preparation and the final signed bundle have their own CI checks.

Hardware validation ran on **wlanpi-d62, then wlanpi-da2**: the real ten-minute fallback, independent AP clients, web/SSH, sensor access over a verified AP/NAT path, management recovery, client retention and idle shutdown passed. Stand/AP DHCP coexisted without restarting provisioning services; external-stop guard cleanup passed on both stations. d62 provisioning DHCP/USB services remained masked while sharing the stand.

The complete simultaneous sensor write/SHA256/OS-check cycle with the AP active and human inspection of AP status on physical HDMI/FPMS displays remain follow-up acceptance. Physical radio removal/rename, reboot/rfkill and real tagged-VLAN forwarding have not all been repeated on hardware; isolated software coverage is broader. FPMS remains **preview**, and the station image remains **experimental**.

This release adds no database migration. Before upgrading, keep a station backup and an alternative management path. Downgrading below this feature retires its owned AP, so an engineer connected through it will need another path.
