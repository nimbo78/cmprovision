# 2.27.1 — Clean update recovery and focused settings 🔧✨

## What changed

- A planned station update no longer leaves a Livewire failure window over the successful result.
  The page shows the ongoing operation, reconnects after the web service returns and refreshes the installed version.
  Authentication/session failures and unexpected server errors retain their normal handling.
  When upgrading from 2.27.0, refresh the page once after completion to load this browser fix; do not apply again.
- Service status and the service journal buttons are available in **Settings → Status**.
  Network, Provisioning, Notifications and Updates no longer repeat the service strip and Logs dropdown.
  Opening these tabs also avoids reading the full server-service list.
- FPMS service names, update confirmation, idle checks, recovery snapshots and automatic rollback are preserved.

## Verification and scope

The complete local PHP suite passed: **2190 tests, 8481 assertions, 27 skips and one existing PHPUnit notice**.
All **84 JavaScript tests** passed. Browser checks cover all five settings tabs at 1920 and 390 pixels,
an actual maintenance HTTP response, a simulated lost connection and automatic return to a completed result without reloading.
An unrelated server failure still opens the normal error window. Independent source review found no actionable issue.

Install from **Settings → Updates** on an idle station. The application update includes matching FPMS Lite
when already installed and keeps the selected Utility OS and prior service states. No database migration is added.
The complete release workflow builds and audits both packages and the ARM64 station image, signs the update metadata
and verifies all uploaded hashes before publication.

The station image remains **experimental** and FPMS remains **preview**. This patch does not replace physical hardware acceptance.
