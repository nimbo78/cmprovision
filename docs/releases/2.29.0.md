# 2.29.0 — Full station backups and update diagnostics 🔐✨

## What changed

- **Settings → System → Backup** can create an encrypted station archive for browser download or verified SFTP, FTP/FTPS and S3 storage. A single master password protects new copies; changing it does not change older archives. Remote credentials are never displayed again.
- Full copies include consistent application data, administrators, SSH access and supported network/Wi-Fi, time, display and web settings. Provisioning images and sensor packages are optional. Existing data-only downloads and selective import/export remain available.
- Daily/weekly schedules are off initially and use the station time zone. Busy stations wait; canceled or interrupted copies release their maintenance gate safely. Remote success requires size/SHA256 read-back and a completion marker; retention touches only this station's recorded copies.
- **`cmprovision-full-restore`** previews an authenticated archive before applying it over SSH. Migration preserves destination network, SSH identity, emergency access and stand role by default. Applying creates a separate recovery archive first; interrupted restoration keeps provisioning blocked until administrator recovery.
- **Settings → Updates** exposes bounded failure details and a password-confirmed diagnostic download. Ordinary check failures and unexpected exceptions retain their phase, reference and safe cause chain. Interrupted read-only HTTP transfers have at most three attempts; installations and signature/checksum failures are never retried.
- Portable FPMS Lite packages without the optional `Installed-Size` header use their registered files for backup space checks.

## Verification and limits

The local suite passed **2195 PHP tests / 8635 assertions**, **89 JavaScript tests**, **77 backup tests** including real loopback transports and multi-gigabyte streaming, and **73 updater tests**. The PHP run retained 27 environment-dependent skips and three existing warnings. Independent review completed, with important findings fixed and verified.

Disposable Debian acceptance covers package installation/downgrade, the headerless FPMS package, accounts, SSH, NetworkManager, SQLite and same-version repair. Failure injection and simulated reboot prove that DHCP/USB boot remains blocked until authenticated recovery.

Physical acceptance and final release CI are recorded in [PR #21](https://github.com/nimbo78/cmprovision/pull/21).

This is a backup of the **supported station configuration**, not an entire Debian disk image. The archive master password is excluded and must be kept separately. Repacked software requires explicit administrator trust before installation. Downloads expire after one hour; restore schedules are disabled and a new master password is required after restoration. See [station backups](../backups.md) and [updater diagnostics](../updates.md#failure-diagnostics).

The loopback FTPS fixture uses TLS 1.2 for a pyftpdlib TLS 1.3 issue; production TLS verification is unchanged. External AWS/MinIO and other real storage-server acceptance remain separate. The station image remains **experimental** and FPMS remains **preview**.
