# 2.27.0 — Подписанные обновления и питание станции 🔐🔌

## Что изменилось

- **Settings → Updates** проверяет и устанавливает стабильные обновления приложения и утилитарной ОС отдельно.
  У каждого компонента есть переключатель ежедневной проверки; проверка сама ничего не устанавливает.
  Скачивание показывает фактический прогресс, затем проверяются подпись издателя и суммы SHA-256.
- Обновление приложения требует свободного стенда, недавнего подтверждения пароля и резервной копии для восстановления.
  Отдельный процесс проверяет установленное приложение и автоматически возвращает предыдущую версию при сбое.
  Установленный FPMS Lite обновляется вместе с приложением; маски служб и выбранная утилитарная ОС сохраняются.
- Состояние обновления, сведения о компонентах и журнал операции обновляются автоматически после перезапуска приложения.
- Отчёты прошивки привязаны к текущему исполнителю; временные ошибки сервера повторяются,
  повторные отчёты о завершении обрабатываются безопасно. Обнаружение станций сверяет LLDP с текущими MAC в таблице коммутации.
- Перезагрузка и выключение провижинера доступны в **Settings → Status → Station power**.
  Веб-интерфейс запрашивает подтверждение пароля учётной записи, затем самого действия.
- Те же действия открываются через **KEY3 на FPMS Lite**, в Classic/New и Light/Dark/Auto.
  Центр джойстика выбирает пункт, **KEY1 подтверждает**, **KEY2 отменяет**. Изначально выбрана отмена.
- При незавершённых или замолчавших прошивках требуется **отдельное предупреждение и подтверждение прерывания**.
  Сервер заново проверяет текущее состояние. После постановки действия в очередь новые прошивки ждут возврата станции.
- Браузер подтверждает перезагрузку только после смены идентификатора загрузки станции.
  Тайм-аут сети или неверный ответ остаётся неподтверждённым результатом.
- Новая стабильная версия в `main` запускает полный выпуск после успешных проверок:
  production-пакеты, образ станции ARM64, аудит артефактов, загрузку и проверенную публикацию.
  Версии для разработки не публикуются; существующие теги и файлы релизов не заменяются.

## Проверка и ограничения эксплуатации

Релизный процесс запускает тесты PHP, JavaScript, FPMS и проверки выпуска, собирает чистые production-пакеты,
проверяет образ, а перед публикацией сверяет загруженный комплект файлов и суммы SHA-256.
Подробные результаты сохраняются в создавшем сборку запуске GitHub Actions.

Действие с питанием начинается примерно через пять секунд после окончательного подтверждения;
отменить его после этого нельзя. Прерывание записи образа или EEPROM может потребовать восстановления платы.
После выключения передёрните **PoE или внешнее питание**, чтобы включить станцию снова.

Образ остаётся **экспериментальным**, FPMS — **предварительной функцией**. Физические KEY1/KEY3,
настоящие перезагрузка и выключение, а также возврат после цикла питания ещё требуют аппаратной приёмки;
автоматическая публикация не означает, что эти проверки выполнены.
Миграция базы не требуется. В сохранённом адаптере полной WLAN Pi OS управления питанием нет.
Устанавливайте обновления только на свободном стенде. Установка пакетов кратковременно перезапускает службы приложения;
она не перезагружает провижинер и не прошивает подключённые сенсоры. Сохраните доступ по SSH для восстановления.
