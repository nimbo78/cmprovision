# cmprovision 2.31.0 — черновик описания версии

Минорный выпуск готовится в отдельной ветке и ещё не опубликован.

## Повторная прошивка совместимых устройств

Откройте Ports, карточку существующего модуля или введите IPv4 через CMs. Совместимый CM4/Pi 4 можно сбросить без локальной истории, метки OURS и доступа к прежнему стенду. Метка остаётся информацией о происхождении.

Общий мастер проверяет доступ, плату, Ethernet MAC, корневой диск и сетевую загрузку перед отдельным подтверждением очистки. Используется активный проект текущего основного провижинера. Вторичная станция открывает явно настроенный основной сервер, передавая только адресные подсказки. История появляется после настоящего старта утилитарной ОС. Смена устройства/проекта, занятые операции станции и истёкшее подтверждение блокируют отправку; неизвестный результат автоматически не повторяется.

Поддерживаются целый диск eMMC/SD, MBR и ext4 на втором корневом разделе. Зарегистрированные агенты v1 сохраняют рабочий путь; незнакомой плате доступен инспектор только для чтения через разрешённую учётку с sudo. Неподдерживаемая разметка и станции блокируются. [Инструкция](../operations.md#re-provision-an-installed-sensor).

## Место, отчёты и образы

- Settings → System → Storage показывает измерения и предпросмотр очистки. Образы проектов, текущих прогонов и подготовки частей защищены от удаления.
- Отчёт устройства скачивается в самостоятельном HTML или JSON с ограниченными диагностическими данными и встроенным шрифтом отчёта.
- Images явно проверяет GitHub на новые подходящие стабильные образы. Скачивание и смена проекта остаются решением оператора.
- При сбое применения DHCP-резерваций возвращаются и данные, и конфигурация.

## Экраны и восстановление

- На HDMI видны аплинки управления: интерфейс, SSID/сигнал либо скорость Ethernet и IP-адреса.
- Rescue AP соблюдает заданные десять минут ожидания; HDMI показывает QR на минуту. Время восстанавливается при обнаружении уже работающей точки.
- В FPMS добавлено подменю Appearance с Light/Dark/Auto. Пользователь проверил Appearance, перезагрузку и выключение на железе.
- PoE restart доступен при поданном питании без Ethernet-линка; соседние станции показываются серой меткой cm.
- Обновление пакета перезапускает работающий общий источник данных HDMI/FPMS. Сборка образа проверяет инициализацию восстановления обновлятора.

[Работа со станцией](../station-operations.md), [резервный Wi-Fi](../rescue-wifi.md), [FPMS](../fpms-display.md).

## Проверки и оставшаяся аппаратная приёмка

После исправлений независимого ревью локально прошли 2361 PHP-тест / 9276 проверок; 90 JavaScript-тестов; 8 проверок настоящего OpenSSH / 17 утверждений. В полном PHP-прогоне остаются три прежних предупреждения и 27 пропусков по окружению; восемь SSH-сценариев проверены отдельно. Стили пересобраны Tailwind 3.4.19.

Все четыре важных замечания ревью покрыты проверками: вход по учётке не обходит защиту станций; таблицы MAC коммутаторов должны указывать на единственный конечный порт; противоречия DHCP одинаково проверяются при выборе по MAC и IP; соответствие серийника и MAC повторно проверяется непосредственно перед сбросом. У известного устройства с недоступными данными BOOT_ORDER показывается предупреждение; явно неподходящий порядок загрузки блокирует сброс.

FPMS остаётся preview, образ станции — experimental. Ещё нужна проверка rescue AP одновременно с настоящей прошивкой.

Пакеты `2.31.0~dev6` (`2008715`) установлены сначала на d62, затем на da2: роли сохранены, перед установкой проверено по одному снимку пакета. На физическом fd3 (CM4 rev 1.0) прошли проверка старого ограниченного ключа и расширенный инспектор через учётку.

Затем на fd3 проверен сброс после сохранения и удаления регистрации. Пока записи Cm не было, расширенный инспектор вошёл через сохранённую учётку WLAN Pi; сброс отправлен один раз, а новая запись появилась после настоящей сетевой загрузки. Полный цикл прошёл SHA256 и проверку ОС за **7:18**, состояние ОС — `running`, EEPROM не менялась. Все **141** строк прежнего журнала сохранены; **4** сохранившиеся ссылки уведомлений перепривязаны к новой записи.
