# Прошивка CM4 через USB

[Назад к README](../../README.ru.md) · [Локальная консоль](local-console.md) · [Оборудование WLAN Pi M4+](hardware/wlanpi-m4-plus.md)

Загрузка по USB позволяет начать прошивку Compute Module 4, даже если установленная система или порядок загрузки EEPROM блокируют сетевую загрузку. Вам не требуется входить в установленную систему или предварительно стирать загрузочный раздел. Модуль CM4 загружает утилитарную ОС в оперативную память (RAM) с помощью `rpiboot`, после чего записывает образ активного проекта на накопитель.

**Подключение Ethernet по-прежнему обязательно.** USB передаёт только загрузочные файлы; утилитарная ОС получает аренду DHCP, скрипт провижининга и образ через Ethernet-порт модуля. Эта процедура не монтирует плату как USB-накопитель и не использует Raspberry Pi Imager или сетевой USB-гаджет установленной ОС. Утилитарная ОС 2026.10.1 также поддерживает [резервную USB-диагностику](module-diagnostics.md#автоматический-резервный-сбор-по-usb), когда сетевой отчёт недоступен; это не заменяет Ethernet для передачи скриптов и образов.

Инструкция рассчитана на платы CM4. Для двух устройств WLAN Pi M4+ используйте [руководство по несущей плате](hardware/wlanpi-m4-plus.md) для определения разъёмов и переключателей BOOT/OTG.

## Что необходимо

- Работающий сервер cmprovision с доступом к веб-интерфейсу.
- Несущая плата CM4 с сервисным портом USB (programming / device port) и доступом к контакту `nRPIBOOT` (часто подписан как `BOOT` или `EMMC-DISABLE`).
- Короткий качественный USB-кабель передачи данных.
- Активный USB-хаб с внешним питанием, достаточным для платы и её периферии.
- Подключения Ethernet от сервера и целевого модуля к изолированному коммутатору стенда.

Raspberry Pi рекомендует использовать активный хаб и короткие кабели для [хостов rpiboot](https://github.com/raspberrypi/usbboot#recommended-rpiboot-host-configuration). Сверяйте требования по питанию и джамперы с документацией несущей платы.

```text
Провижинер USB-A ── активный USB-хаб ── кабель USB ── сервисный порт модуля

Провижинер eth0 ── изолированный коммутатор ── Ethernet модуля
                                               PoE отключено для питания по USB
```

Провижинер является USB-**хостом**; прошиваемый модуль — USB-**устройством** (device). Если оба устройства — M4+, переключайте BOOT/OTG только на целевом модуле, сохраняя сервер в рабочей конфигурации хоста.

## Подготовка проекта

Запись образа перезаписывает систему и данные модуля. Выберите накопитель перед включением загрузки по USB.

1. Убедитесь, что на стенде нет активных прошивок. В **Projects → Add project** выберите образ из раздела **Images**, для которого завершён подсчёт сумм.
2. Укажите **Destination storage device**. CM4 с eMMC обычно использует `/dev/mmcblk0`; проверьте плату перед выбором другого пути.
3. Включите **Verify that image was written correctly**.
4. Опцию **EEPROM firmware update to apply** можно оставить в `-none-`. Загрузка по USB не требует изменения порядка загрузки EEPROM.
5. Опцию **Check the OS after the first boot** можно оставить включённой, но для USB-загрузки она автоматически пропускается. First-boot скрипты и пакеты также пропускаются; стандартные скрипты pre-install и post-install выполняются штатно.
6. Опция **Re-provision from the web UI** настраивается по желанию (для [повторного провижининга по SSH](operations.md#повторный-провижининг-установленного-сенсора)).
7. Нажмите **Save** и активируйте проект кнопкой **Set active**. Активный проект применяется ко всему стенду: убедитесь, что другие модули не начнут прошиваться под этим проектом.

## Запуск через USB

1. В **Settings → Utility OS** выберите раздачу нужной ОС (64-битная или устаревшая 32-битная). Активная строка отмечена как **modules get this one**. Не переключайте ОС во время загрузки плат.
2. В **Settings → Status** найдите службу **rpiboot (USB file server)** и откройте **View log**. Ожидание подключения устройства в логе является нормальным.
3. Полностью обесточьте целевой модуль: отключите USB и снимите другие источники питания. Для схемы выше отключите PoE на порту коммутатора, оставив передачу данных включённой.
4. При выключенном питании переведите USB несущей платы в режим **Device** и замкните контакт `nRPIBOOT`/`BOOT`. Это разные контакты: один режим Device не переводит CM4 в ROM-загрузку по USB. Для M4+ используйте [таблицу перемычек платы](hardware/wlanpi-m4-plus.md#boot-and-usb-role-controls).
5. Подключите активный хаб к порту USB-A провижинера и подайте питание на хаб. Подключите Ethernet модуля к коммутатору стенда.
6. Соедините порт хаба с сервисным разъёмом модуля USB. Это подаст питание на модуль в указанной схеме. Следите за логом rpiboot: обнаружение устройства и передача файлов отобразятся в журнале. Встроенная служба cmprovision уже запускает rpiboot; ручной запуск второй копии не требуется.
7. Откройте страницу **CMs** и MAC-адрес модуля. Проверьте проект, образ и версию утилитарной ОС. Следите за этапами записи и сверки до статуса **Done**.

Если проверка ОС была включена, в карточке появится пометка **skipped: the module booted over USB**. Модуль остаётся в утилитарной ОС после окончания прошивки. Он автоматически не перезагружается в записанный образ, иначе принудительный USB-boot вернул бы его в прошивку по USB. [Светодиодные сигналы](leds.md) и функция **Identify** помогут найти готовый модуль.

## Запуск записанной системы

1. После перехода в статус **Done** отключите кабель USB от модуля и снимите питание. Простое отключение PoE не обесточивает плату, питающуюся по USB.
2. Разомкните контакты `nRPIBOOT`/`BOOT` и верните USB несущей платы в режим **Host**.
3. Отключите USB-связь с сервером. При необходимости верните исходный активный проект на сервере.
4. Подайте стандартное питание на модуль (например, включите PoE). Модуль загрузит записанную систему согласно настройкам EEPROM (порядок должен разрешать загрузку с eMMC/SD).

Обычный запуск не превращает статус USB-прогона **OS check: skipped** в **passed**. Для полной валидации скриптов первого запуска выполните отдельный [сетевой прогон с проверкой ОС](operations.md#проверка-ос-при-первой-загрузке).

## Подготовка платы к сетевой загрузке (USB prep)

Для смены загрузочного порядка без записи ОС используйте отдельную [иллюстрированную инструкцию USB prep](usb-prep.md). В ней есть схема этапов, перемычки M4+, состояния Dashboard и проверка результата.

USB prep меняет только EEPROM. Образ записывается позже по Ethernet на PoE-стенде; на обоих этапах нужен Ethernet.

## Устранение неполадок

| Наблюдаемое поведение | Что проверить |
| --- | --- |
| rpiboot ожидает, пока модуль грузит свою ОС | Модуль не перешёл в ROM-загрузку по USB; проверьте контакт BOOT/nRPIBOOT |
| Нет обнаружения по USB | Режим Device на плате, кабель с линиями данных, сервисный порт и питание модуля |
| Обрывы связи до завершения передачи | Блок питания, мощность активного хаба и качество кабеля |
| Ошибка `Failed to open second stage bootloader` | Каталог утилитарной ОС должен содержать валидный `bootfiles.bin`; см. [Утилитарная ОС](utility-os.md) |
| Передача останавливается после `start4.elf` / `fixup4.dat` до ядра | Проверьте, что служба rpiboot раздаёт каталог `etc/boot/usb`; файлы `config.txt` и `boot.img` обеспечивают USB ramdisk для CM4 |
| Файлы переданы, но прогон не появляется | Подключение Ethernet модуля, DHCP и доступность адреса провижинера (`172.20.0.1`) |
| Карточка просит подтвердить текущий проект | Выполните подтверждение проекта повторного провижининга, затем перезапустите модуль |
| Ошибка сверки (verification fails) | Изучите журнал модуля перед повтором; передача файлов по USB не гарантирует исправности eMMC |
| Не работает USB-клавиатура на M4+ | Режим Device отключает порты USB-A; переключите в Host для работы с [локальной консолью](local-console.md) |

Для непрерывного просмотра лога выполните на провижинере:

```sh
sudo journalctl -u cmprovision-rpiboot -f
```
