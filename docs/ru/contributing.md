# Гайдлайн по участию и стиль проекта ✨💅

Добро пожаловать в **cmprovision**! В этом документе зафиксированы наши стандарты по коммитам, пулл-реквестам (PR), мердж-реквестам (MR), релизам и совместной разработке с AI-агентами.

---

## 🌟 Вайб: Зумерский билингвал + Железная точность 🚀💯

Мы держим баланс между дружелюбным стилем и бескомпромиссным техническим качеством:
- **Паритет двух языков (Dual-Language):** Заголовки PR, краткие саммари, документация и анонсы релизов пишутся параллельно на английском и русском.
- **Энергичные эмодзи и современный сленг:** Отмечаем релизы и поставки со вкусом (*Glow Up, Drop, What's Cookin', no cap, на ультра-вайбе, без кринжа, лютый, годнота*).
- **Железные пруфы без воды:** Шутки не заменяют факты. Каждое изменение сопровождается точными цифрами тестов, шагами воспроизведения, изоляцией в git worktree и анализом возможных рисков.

## 📦 Стандарт коммитов (Conventional Commits)

Мы следуем спецификации [Conventional Commits](https://www.conventionalcommits.org/):

```text
<тип>(<область>): <краткое описание в повелительном наклонении>
```

- **Типы:**
  - `feat`: Новая пользовательская функциональность.
  - `fix`: Исправление ошибки или бага.
  - `docs`: Документация, гайды, диаграммы и переводы.
  - `test`: Добавление или рефакторинг юнит/интеграционных тестов.
  - `refactor`: Изменение структуры кода без изменения его поведения.
  - `perf`: Оптимизация производительности.
  - `chore`: CI, сборочные скрипты, debian-пакеты, зависимости.
- **Примеры:**
  - `docs(diagrams): add interactive Archify provisioning workflow diagram (EN and RU)`
  - `feat(transfer): add selective configuration transfer and creation wizards`
  - `fix(settings): fix literal Blade directives in Settings service summary`

Шаблон:

**Примеры:**
- `📚 Dual-Language Glow Up: Bilingual English & Russian Docs Drop ✨🔥 / Завезли лютый билингвал: фулл дока на инглише и русском на ультра-вайбе 💅🌐`

- `🚀 Selective Config Transfer & Wizard Glow-Up ✨🧙‍♂️ / Селективный перенос конфигов и лютые визарды 📦⚡`

## 📝 Структура описания PR и MR

Каждый PR оформляется строго по шаблону (`.github/pull_request_template.md`):

1. **`## 🌟 What's Cookin'? / Чо за движ тут происходит? ✨💅`**: Билингвальное вводное саммари.
2. **`### 🎨 What Changed? / Что завезли в этом дропе? 🖼️⚡`**: Попунктный список изменений, компонентов и визуальных ассетов со ссылками на файлы.
3. **`### 🧪 Verification / Тесты и валидация 💯`**:
   - Количество пройденных тестов `php artisan test`.
   - Количество пройденных тестов `npm run test:js`.
   - Проверка на реальном железе (`wlanpi-da2`, `d62`) или в Docker-стенде.
   - Изоляция ветки в отдельном git worktree.
4. **`### ⚠️ Merge Danger & Blast Radius / Риски и влияние 🛡️`**:
   - Тип двери (one-way / two-way с бэкапом).
   - Затронутые подсистемы (миграции БД, очереди, dnsmasq, nginx, только доки).

## 🚀 Стандарт описания релизов (Release Notes)

Релизы на GitHub публикуются в нашем фирменном двуязычном формате:
- Цепляющий двуязычный заголовок с номером версии и ключевыми фичами.
- **What's Cookin' / Главный замес**: Вводный анонс релиза.
- **What's in the Box / Что завезли**: Подробный разбор функциональности с акцентом на безопасность и UX.
- **Quality Assurance & Evidence / Пруфы и тесты**: Метрики тестирования и результаты проверки на стендах.
- **How to Upgrade / Как накатить обновление**: Инструкция по установке пакета, проверка контрольных сумм и предупреждение о бэкапе.
