# Обновление и восстановление

[Назад к README](../../README.ru.md) · [Эксплуатация провижинера](operations.md)

## Установка поверх существующего пакета

Стабильный релиз содержит оба Debian-пакета, экспериментальный образ станции и контрольные суммы.
Он публикуется автоматически после успешных проверок `main`, полной сборки и аудита;
версии для разработки не публикуются. [Описание автоматизации](../../image/README.md#automatic-complete-releases).
Публикация не устанавливает обновление на работающую станцию и не заменяет аппаратную приёмку.

После установки пакета с обновлятором раздел [Settings → Updates](updates.md) позволяет загрузить
и установить подписанный стабильный релиз на свободной станции с обязательной копией и автооткатом.
Приложение и Utility OS обновляются независимо. Ручная установка пакета ниже также остаётся доступна.

Версия 2.6.4 добавляет функцию Identify после проверки ОС при первой загрузке (до следующей перезагрузки модуля). Миграции базы данных не требуются. Ранее прошитые сенсоры сохраняют свой скрипт первой загрузки: обновление одного сервера не добавляет им опрос. Прошейте их повторно на обновлённом сервере для получения новой функциональности. См. [проверку ОС при первой загрузке](operations.md#проверка-ос-при-первой-загрузке).

Миграция версии 2.6.3 добавляет снимок целевого диска для каждого прогона. Старые отметки возобновления не содержат такого снимка и однократно сбрасываются при обновлении: прерванный старый прогон начнется с начала. Новые прогоны сохраняют штатную докачку кусков. Опция проекта повторного провижининга по умолчанию отключена. При обновлении со сборок разработки 2.6.3, где миграция уже применялась, повторный сброс не выполняется.

> [!IMPORTANT]
> Никогда не выполняйте `apt remove` перед обновлением: удаление пакета удаляет базу данных и хранилище.

```sh
sudo apt install ./cmprovision4_*_all.deb
```

Обновите открытые вкладки браузера после завершения установки.

## Резервные копии и откат

Каждое обновление автоматически создаёт снимок данных в `/var/backups/cmprovision/<timestamp>-<старая-версия>/` перед распаковкой нового пакета (начиная с 2.17.0 также при обновлении с 2.5 и новее; до этого — только при обновлении со старых версий). Для снимка требуется свободное место в двойном объёме данных приложения (без загруженных образов). При обновлении с версии ниже 2.5 (1.x или 2.0–2.4) сбой всех трёх попыток создания снимка останавливает обновление, оставляя старую версию: повторите попытку, когда на стенде нет активных модулей. Начиная с 2.5, невозможность создания снимка (занятый сервер, нехватка места) выводится предупреждением, а обновление продолжается; сделайте снимок вручную командой `cmprovision-backup`. Сохраняются пять последних снимков, более старые автоматически удаляются.

Для восстановления конкретной версии и её данных:

```sh
sudo cmprovision-restore "/var/backups/cmprovision/<снимок>"
```

Для создания снимка в любое другое время (например, перед изменением настроек) установите `dpkg-repack`, чтобы бэкап содержал установленный `.deb` пакет:

```sh
sudo apt install dpkg-repack
sudo cmprovision-backup
```

Замените `<снимок>` на фактический каталог бэкапа. По умолчанию резервные копии не включают загруженные образы ОС и пакеты. Используйте `sudo cmprovision-backup --with-uploads` для их включения.

Снимки занимают по 100–150 МБ каждый, поэтому сохраняются только пять последних. Флаг `--keep N` (или переменная `CMPROVISION_BACKUP_KEEP=N`) задаёт другое количество, а `--keep all` сохраняет все снимки. Команда `sudo cmprovision-backup --prune` выполняет очистку без создания нового снимка. Удаляются только каталоги вида `<дата>-<время>-<версия>`; вручную указанный путь очищается только при явном вызове `--prune`.

### Резервная копия для внешнего хранения

Снимки на сервере не спасают при выходе из строя накопителя или платы. Кнопка **Settings → System → Backup → Download backup** (с 2.20.0) формирует архив для внешнего хранения с повторным запросом пароля администратора. В него входят база данных, настройки, хранилище прошивок, SSH-ключ повторного провижининга, `.env` и конфигурация DHCP. Тяжёлые файлы образов, пакеты проверки ОС и системные конфиги (сайт nginx, php.ini, сеть) в него не входят.

На экране пароля и странице подготовки есть **Back to Backup**. Подготовка запускается автоматически с индикатором ожидания. **Download started** означает передачу файла браузеру; прогресс и завершение скачивания смотрите в его списке загрузок. Архив скачивается напрямую, без буферизации в памяти страницы.

Файл содержит ключ приложения (APP_KEY) и все сохранённые пароли сервера (коммутаторы, принтеры, боты, учётные записи сенсоров), поэтому требует строго конфиденциального хранения. Каждое скачивание фиксируется в журнале Laravel (пользователь и размер).

Для восстановления на сервере с установленным пакетом `cmprovision4` (на новом или после чистой переустановки):

```sh
tar xf cmprovision-backup-<host>-<date>-<version>.tar
sudo cmprovision-restore --data-only <date>-<version>
```

Файл представляет собой tar-архив каталога с файлами `database.sqlite` и `app.tar.gz`. Флаг `--data-only` восстанавливает данные, применяет миграции установленной версии пакета и перезапускает службы. Образы ОС загружаются заново либо восстанавливаются из бэкапа `--with-uploads`.

Без пакета в снимке `cmprovision-restore` откажется накатывать его поверх другой версии пакета. Скрипты поставляются в пакете: исходники находятся в [`tools/backup.sh`](../../tools/backup.sh) и [`tools/restore.sh`](../../tools/restore.sh).

Аварийный пропуск автоматического снимка при обновлении:

```sh
sudo CMPROVISION_NO_SNAPSHOT=1 apt install ./cmprovision4_*_all.deb
```

## Исправления безопасности PHP

Уязвимости CVE-2026-109618 и CVE-2026-109619 затрагивают сам интерпретатор PHP. Используйте исправленные патч-релизы для каждой поддерживаемой ветки:

| Ветка | Минимальная версия |
| --- | --- |
| PHP 8.3 | 8.3.36 |
| PHP 8.4 | 8.4.27 |
| PHP 8.5 | 8.5.12 |

См. [официальное объявление безопасности PHP](https://www.php.net/archive/2026.php) и бюллетени [CVE-2026-109618](https://github.com/php/php-src/security/advisories/GHSA-w8hw-w9fx-j79w) и [CVE-2026-109619](https://github.com/php/php-src/security/advisories/GHSA-6wmf-4rv5-p3rp).
Пакет требует конкретные исправленные версии пакетов CLI и FPM; метапакеты `php-cli` и `php-fpm` не гарантируют наличия патча. Обновляйте через `apt` после обновления индексов репозитория.

В Debian 13 / Raspberry Pi OS Trixie обновите PHP 8.4 при отсутствии активных прошивок:

```sh
sudo apt update
sudo apt install --only-upgrade php8.4-cli php8.4-fpm
sudo systemctl restart php8.4-fpm cmprovision-queue cmprovision-queue-images
php -v
php-fpm8.4 -v
```

Перезапуск воркеров очереди обновляет их фоновые PHP-процессы. Проверьте **Settings → Status** и обновите веб-интерфейс.

Composer поддерживает исправленные ветки. Значение `config.platform.php = 8.3.36` служит целевым ориентиром разрешения зависимостей. Проверка зависимостей платформы:

```sh
composer check-platform-reqs --lock --no-dev
```

Команда проверяет CLI; версию FPM проверяйте отдельно. Сборка Docker проверяет установленный PHP по lock-файлу. Настройки Upload Progress и лимиты загрузки остаются штатными; отключение Upload Progress после установки патча не требуется.

## PHP и воркеры очереди

Начиная с 2.5 веб-интерфейс работает в собственном пуле PHP-FPM, рассчитанном на одновременный старт партий из 40–48 модулей. Пул настраивается в `/etc/php/<версия>/fpm/pool.d/cmprovision.conf` и использует сокет `/run/php/cmprovision-fpm.sock`.

После обновления версии PHP пересоздайте пул:

```sh
sudo dpkg-reconfigure cmprovision4
```

Рядом с веб-интерфейсом работают два воркера:

| Служба | Задачи |
| --- | --- |
| `cmprovision-queue` | Опрос портов коммутаторов и отправка уведомлений |
| `cmprovision-queue-images` | Подсчёт контрольных сумм и обработка образов; подхват опроса портов при занятости первого воркера |

Раздел **Settings → Status** отображает оба воркера и их журналы. Модуль получает скрипт мгновенно; привязка к порту появляется через несколько секунд. Уведомления группируются по одному сообщению на канал каждые 10 секунд.

SQLite работает в режиме WAL. Выполняйте ручные команды `artisan` и `sqlite3` от имени `www-data`:

```sh
sudo -u www-data /var/lib/cmprovision/artisan about
```

## Настройки коммутаторов из 2.3 и 2.4

Версия 2.4 переносит коммутаторы в отдельный список, преобразуя настройки 2.3 в первую запись. Настройки 2.3 сохраняются для отката.

- Восстановление снимка 2.3 восстанавливает базу данных. Следующее обновление пересоздаст список коммутаторов из этих настроек.
- Установка пакета 2.3 поверх 2.4 без восстановления снимка сохраняет список 2.4.

Проверьте **Settings → Ethernet switches** в обоих случаях.

## Другие изменения при установке

Этап post-installation автоматически настраивает существующие серверы:

- nginx получает `send_timeout 6h` для длительной отдачи образов.
- Параметр PHP `upload_tmp_dir` переносится на диск рядом с образами.
- В `.env` задаются `APP_ENV=production` и `APP_DEBUG=false`.
- Каналы прошивок переименованы из `stable`/`beta` в `default`/`latest`.

## Сетевые роли в резервных копиях

Полные снимки начиная с версии 2.24.0 сохраняют маски служб DHCP/TFTP и USB, а также загрузочные ссылки вместе с конфигурацией сети. Полное восстановление восстанавливает роль станции по этим ссылкам. Старые снимки без этих метаданных сохраняют текущую роль служб. Режим `--data-only` также сохраняет текущую роль системы. Подтвердите или отмените незавершённые изменения сети перед бэкапом или восстановлением.
