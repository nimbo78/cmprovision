# Локальная консоль целевого модуля

[Назад к README](../../README.ru.md) · [Прошивка через USB](usb-provisioning.md) · [Оборудование WLAN Pi M4+](hardware/wlanpi-m4-plus.md)

Утилитарная ОС предоставляет локальную командную оболочку на **tty2**. Используйте её для диагностики модуля при невозможности получить IP-адрес, загрузить скрипт прошивки или передать отчёт на сервер. Скрипт провижининга продолжает работу на **tty1**, пока вы работаете в tty2.

Это консоль **самого прошиваемого модуля**. Клавиатура, подключённая к серверу-провижинеру, сессия SSH к провижинеру или консоль разработчика в браузере не открывают tty2 модуля. Утилитарная ОС не запускает сетевых служб входа (SSH или telnet). Локальная учётная запись root не имеет пароля, поэтому физический доступ к консоли даёт полный контроль над временной системой.

## Подключение экрана и клавиатуры

Вам понадобятся несущая плата модуля с доступным выходом HDMI, монитор и проводная USB-клавиатура. На WLAN Pi M4+ используйте полноразмерный разъём HDMI; компактный встроенный ЖК-экран не настраивается как системная консоль Linux в этой утилитарной ОС.

```text
Провижинер eth0 ── изолированный коммутатор ── целевой Ethernet / стандартное питание платы
                                                ├─ HDMI ── монитор
                                                └─ USB host port ── клавиатура
```

1. Полностью обесточьте целевой модуль перед переключением перемычек и подключением кабелей.
2. Отключите принудительную загрузку по USB (BOOT/nRPIBOOT) и переведите USB-контроллер в режим **Host**. Подключите клавиатуру к хост-порту USB модуля, а монитор — к выходу HDMI модуля. Выберите соответствующий вход на мониторе.
3. Подключите модуль к сети провижининга и подайте питание. Для платы WLAN Pi M4+ [ознакомьтесь с переключателями BOOT/OTG](hardware/wlanpi-m4-plus.md#boot-and-usb-role-controls).
4. Загрузите модуль в утилитарную ОС по сети. Если на модуле уже установлена система, используйте [процедуру повторного провижининга](operations.md#повторный-провижининг-установленного-сенсора) для её замены. Обычный перезапуск загрузочной eMMC не приводит к сетевой загрузке утилитарной ОС.

На M4+ эта схема отличается от прошивки по USB: режим USB Device отключает порты USB-A. Для работы с локальной клавиатурой используйте сетевую загрузку и режим Host.

## Переход на tty2

1. После загрузки утилитарной ОС нажмите **Alt+F2** на клавиатуре модуля (комбинация **Ctrl+Alt+F2** также поддерживается; на клавиатурах с мультимедийными клавишами может потребоваться зажать **Fn**).
2. В строке приглашения входа введите `root`. При запросе пароля нажмите Enter без ввода символов. Это учётные данные временной утилитарной ОС, а не записываемого образа.
3. Выполните `tty`. Вывод должен содержать `/dev/tty2`.
4. Нажмите **Alt+F1** для просмотра вывода скрипта провижининга, затем **Alt+F2** для возврата в командную строку. Переключение виртуальных консолей не прерывает запись или сверку образа.

Если долго работающая диагностическая утилита заняла консоль, нажмите Ctrl+C для её остановки. Не перезагружайте модуль, не монтируйте накопители в режиме записи и не завершайте системные процессы во время записи образа, обновления EEPROM или сверки данных.

## Проверка запущенной системы

Выполните следующие команды на tty2 модуля:

```sh
tty
uname -r
uname -m
cat /etc/cmprovision-uos
tr -d '\000' </proc/device-tree/serial-number
echo
cat /proc/mounts
```

Для Utility OS 2026.10 ожидается консоль `/dev/tty2`, ядро `6.18.50-cmprovision`, архитектура `aarch64` и версия `2026.10`. Последующие релизы сообщают собственные версии. Устаревшая 32-битная ОС не имеет файла `/etc/cmprovision-uos`; отсутствие этого файла само по себе не является ошибкой.

Корневая файловая система утилитарной ОС временная и размещается в оперативной памяти (RAM). Скрипт провижининга может временно монтировать разделы накопителя на этапе post-install. После перезагрузки на этапе OS check консоль передаётся **установленной операционной системе** с её собственными пользователями, паролями и утилитами; маркер версии утилитарной ОС больше не присутствует.

## Диагностика остановки на старте

Команды проверки состояния без изменения накопителя:

| Задача | Команда |
| --- | --- |
| Есть ли линк на Ethernet? | `cat /sys/class/net/eth0/carrier` — `1` означает линк, `0` — нет линка |
| Получен ли адрес IPv4? | `ip -4 addr show eth0` |
| Какие маршруты присутствуют? | `ip route` |
| Доступен ли адрес провижинера? | `ping -c 3 172.20.0.1` |
| Видит ли ядро накопитель? | `cat /proc/partitions` |
| Что сообщает буфер ядра? | `dmesg` |
| Какие процессы активны? | `ps` |

Модуль в стандартной сети стенда получает адрес из диапазона `172.20.0.0/16`. При отсутствии несущей (`carrier = 0`) проверьте патч-корд и порт коммутатора. Если линк есть, но адрес не получен, проверьте службы DHCP/TFTP в разделе **Settings → Status** на сервере-провижинере. Если адрес есть, но скрипт не выполняется, сопоставьте сообщения на tty1 с журналами сервера.

Переход на tty2 не регистрирует успешное окончание провижининга. Дождитесь штатного завершения записи и сверки; если в проекте включена проверка ОС, дождитесь статуса **OS check: passed** и фазы **Done** в карточке модуля.

## Если консоль не отображается

| Симптом | Проверка |
| --- | --- |
| Нет изображения | Разъём HDMI модуля, видеовход монитора, кабель и питание модуля |
| Есть картинка, но нет реакции на клавиатуру | Режим USB Host на плате и надёжность подключения клавиатуры к порту модуля |
| Маленький экран M4+ ничего не показывает | Используйте HDMI; утилитарная ОС не запускает графическое приложение WLAN Pi |
| Приглашение входа или имя хоста соответствуют целевому образу | Проверьте сетевую загрузку утилитарной ОС по tty1, `uname` и маркеру версии |
| Ошибка SSH к модулю | Сетевой шелл отсутствует в утилитарной ОС; используйте локальный tty2 |

Подключение USB-UART является отдельной последовательной консолью и не проверяет работу tty2.
