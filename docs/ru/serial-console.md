# Подключение к последовательной консоли по USB

Из SSH-сеанса на провижинере можно открыть консоль коммутатора или платы через локальный USB-адаптер FTDI или PL2303. Сверьте уровни напряжения и распайку кабеля для своего устройства. Консоль Catalyst с разъёмом RJ45 использует RS-232, UART на GPIO модуля CM4 — логику 3,3 В. Перед перестановкой перемычки OTG обесточьте плату.

## Выберите физический порт

```sh
cmprovision-console list
```

Скопируйте целиком идентификатор `by-id/…` или `by-path/…`. Команда также показывает интерфейс USB и драйвер ядра. Если у адаптеров совпадают или отсутствуют серийные номера, выберите физический путь. При перестановке адаптера в другой USB-разъём выведите список заново. Для многопортового адаптера сверьте интерфейс и номер порта с подключённым устройством.

## Переходите между устройствами в одном окне SSH

Запустите команду от своей обычной учётной записи с доступом к порту (как правило, через группу `dialout`). Подставьте идентификатор USB из вывода `list`.

```sh
cmprovision-console connect --port 'by-id/usb-EXAMPLE-if00-port0'
```

По умолчанию `connect` вызывает `sudo` для проверки пяти скоростей с форматами **8N1, 8N2, 7E1, 8E1, 7O1 и 8O1**, затем открывает `picocom` от вашего имени. Один проход Auto занимает до 40 секунд. Детектор пропускает форматы, отклонённые драйвером, и отбрасывает порции данных с отмеченными ошибками чётности или кадра. Если на одной скорости несколько форматов дважды дали читаемый текст, команда перечислит их и выберет первый в указанном порядке. Например, `Readable on RX: 8N1, 8N2. Using 8N1.` означает, что адаптер прочитал данные в обоих форматах. При паузах между символами они могут выглядеть одинаково. Если для передачи устройство требует конкретный формат, укажите его явно. [Режимы терминала Linux](https://man7.org/linux/man-pages/man3/termios.3.html)

Переставьте кабель на следующее устройство. Пока текст читается, сеанс продолжится. При устойчивом потоке нечитаемых символов обёртка заново подберёт скорость и формат и откроет терминал в том же окне. Пауза в выводе сохраняет текущее подключение. Этот режим рассчитан на текстовые консоли.

Для проверки по требованию нажмите **Ctrl+]** в открытом терминале. Во время подбора команда ждёт узнаваемого вывода устройства. Если оно молчит, ожидание продолжается до следующей передачи. **Ctrl+C** отменяет подбор. Для выхода из подключённого терминала нажмите **Ctrl+A**, затем **Ctrl+X**. Если отключили сам USB-адаптер, выведите список портов и выберите его заново.

## Определите скорость

Подставьте идентификатор из списка своей станции. Для проверки владельцев терминала нужны права администратора.

```sh
sudo cmprovision-console detect --port 'by-id/usb-EXAMPLE-if00-port0' --profile cisco --target switch01
```

Для разовой проверки используйте `detect --profile auto`. Разовый `detect` без профиля сохраняет прежнее значение 8N1. Именованный профиль `cisco` задаёт 8N2. Для Catalyst 2960-CX Cisco указывает заводские настройки 9600 8N1. Формат также можно задать явно, например `7e1`. [Руководство Cisco](https://www.cisco.com/c/en/us/td/docs/switches/lan/catalyst2960cx_3650cx/hardware/installation/guide/b_2960cx-3560cx_hig.pdf)

FTDI поддерживает 7 или 8 бит данных. Детектор сверяет скорость, формат и управление потоком с настройками, которые принял драйвер. С заданным профилем он проверяет узнаваемый вывод в двух отдельных интервалах до 1,5 секунды каждый. Общий предел разовой проверки с заданным профилем — 12 секунд. [Драйвер FTDI в Linux](https://github.com/torvalds/linux/blob/master/drivers/usb/serial/ftdi_sio.c)

| Результат | Что делать |
|---|---|
| `detected` | Одна скорость подтвердилась в двух интервалах. Выполните предложенную команду `picocom` от своей учётной записи. |
| `silent` | За интервалы наблюдения детектор не прочитал ни байта. Короткая передача могла попасть в паузу после смены скорости, когда очередь очищается. Если скорость известна, откройте сеанс вручную. |
| `inconclusive` | Получены помехи, одиночный фрагмент или сообщения на нескольких скоростях. Дождитесь повторяющегося вывода или задайте скорость вручную. |
| `busy` | Линию занимает процесс, служба или блокировка терминала. Завершите действующий сеанс перед повторной попыткой. |
| `unavailable` | Проверьте адаптер, права и актуальный идентификатор. Команда выводит причину, если её удалось установить. |

Необязательная метка `--target` сохраняет последнюю подтверждённую скорость и время для конкретного устройства, подключения USB и профиля. Если переставили разъём со стороны оборудования, смените метку. При следующем запуске эта скорость проверяется первой и требует свежего подтверждения. Принятый текст консоли отбрасывается.

## Откройте ручной сеанс

Используйте учётную запись с доступом к адаптеру, обычно через группу `dialout`. Для Catalyst с известной скоростью 9600 бод команда выглядит так.

```sh
picocom --baud 9600 --databits 8 --parity n --stopbits 2 --flow n /dev/serial/by-id/usb-EXAMPLE-if00-port0
```

Для выхода нажмите **Ctrl+A**, затем **Ctrl+X**. Готовый образ станции включает picocom. При установке отдельным пакетом недостающий терминал можно добавить из пакета Debian `picocom`. [Руководство picocom](https://manpages.debian.org/trixie/picocom/picocom.1.en.html)

Во время определения скорости команда открывает порт для чтения. При открытии или закрытии полного кабеля драйвер может переключить DTR/RTS, а до настройки терминала Linux может вернуть полученные байты эхом. Если на вход устройства не должен попасть ни один сигнал, подключите только RX станции и общую землю с согласованными уровнями. Для удалённого консольного сервера задавайте скорость на его физической последовательной линии. [Режимы терминала Linux](https://man7.org/linux/man-pages/man3/termios.3.html)
