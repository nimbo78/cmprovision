# HTTP API

[Назад к README](../../README.ru.md)

Создайте токен на странице API-токенов вашего профиля с правами, необходимыми для интеграции (`create`, `read`, `update`, `delete`). Передавайте его в заголовке `Authorization`:

```sh
curl --fail --show-error \
  -H "Authorization: Bearer $CMPROVISION_TOKEN" \
  -H "Accept: application/json" \
  "http://<server-wifi-address>/api/projects"
```

Замените адрес сервера и укажите ваш токен в переменной `CMPROVISION_TOKEN` перед запуском примера. Все маршруты ниже требуют аутентификации по токену. Операции изменения данных дополнительно проверяют соответствующие права: `create`, `update` или `delete`.

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/api/cms` | Список модулей |
| GET | `/api/projects` | Список проектов со скриптами |
| GET | `/api/projects/{id}` | Получение проекта со скриптами |
| GET | `/api/projects/{id}/cms` | Список модулей проекта |
| GET | `/api/images`, `/api/images/{id}` | Список образов или данные образа; загружаемый из интернета образ показывает `download_state` до готовности (проект не может использовать его раньше), а исходный адрес никогда не возвращается |
| GET | `/api/firmware` | Список прошивок |
| GET | `/api/scripts`, `/api/scripts/{id}` | Список скриптов или данные скрипта |
| GET | `/api/labels` | Список меток |
| POST | `/api/images` | Загрузка файла образа через multipart-поле `image` |
| DELETE | `/api/images/{id}` | Удаление образа; если файл скачивается из интернета, загрузка отменяется и временные данные удаляются |
| PATCH | `/api/projects/{id}` | Обновление полей проекта и привязанных скриптов |
| POST | `/api/scripts` | Создание скрипта |
| PATCH | `/api/scripts/{id}` | Обновление скрипта |
| DELETE | `/api/scripts/{id}` | Удаление неиспользуемого скрипта |

При обновлении проекта поле `scripts` должно содержать **полный список** идентификаторов скриптов для привязки. Изменение активного проекта пересобирает образ EEPROM, который скачивают модули. Скрипты первой загрузки (first-boot) и момент печати наклейки `firstboot` требуют включённой опции `os_check`.

Логический параметр проекта `reprovision` по умолчанию равен `false`. Установка в `true` включает в будущие прогоны установку ограниченного публичного ключа провижинера и агента; это действие не стирает сенсор. Проверенное действие повторного провижининга с подтверждением доступно в карточке модуля. См. [повторный провижининг](operations.md#повторный-провижининг-установленного-сенсора).

Скрипты имеют тип `preinstall`, `postinstall` или `firstboot`. Попытка удаления скрипта, используемого проектом, возвращает HTTP 409. Валидация запросов и полные описания полей находятся в файле [`routes/api.php`](../../routes/api.php).
