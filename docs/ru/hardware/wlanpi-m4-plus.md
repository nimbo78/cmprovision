# WLAN Pi M4+ как провижинер и целевой модуль

[Назад к README](../../../README.ru.md) · [Прошивка через USB](../usb-provisioning.md) · [Локальная консоль](../local-console.md)

Два устройства WLAN Pi M4+ могут выполнять разные роли на одном стенде:

| Роль | Что запущено | Что подключается |
| --- | --- | --- |
| Провижинер | Установленная ОС и cmprovision | Сеть управления, изолированный стенд Ethernet, порт USB Host при использовании rpiboot |
| Целевой модуль / сенсор | Временная утилитарная ОС, затем записанный образ на накопителе | Ethernet стенда; сервисный кабель USB либо монитор HDMI и клавиатура |

Сохраняйте провижинер в рабочей конфигурации хоста. Изменяйте переключатели загрузки, перезаписывайте накопитель и подключайте клавиатуру диагностики только на целевом модуле.
Проверяйте установленный модуль CM4: сборки M4+ могут иметь различные конфигурации RAM и накопителя. CM4 с чипом eMMC использует именно eMMC; слот microSD на плате не превращает его в CM4 Lite.

## Расположение сервисного разъёма

На [иллюстрациях платы в обсуждении WLAN Pi #101](https://github.com/orgs/WLAN-Pi/discussions/101) показаны как стандартная фиолетовая плата Mcuzone CM4 WiFi7 PoE, так и зелёная модификация WLAN Pi. Их разводка отличается даже при схожем названии. Ориентируйтесь на маркировку шелкографии и переключатели вашей платы.

- На подписанной фиолетовой плате используйте порт USB-C **power and Program** со стороны HDMI. Противоположный USB-C подписан как **AUX power (opt)** и предназначен только для питания.
- На зелёной плате WLAN Pi порт USB-C с поддержкой данных также расположен со стороны HDMI.
- Контакты BOOT/OTG расположены рядом с разъёмом вентилятора и колодкой GPIO. Кнопки A/B/C на передней панели не управляют ROM-загрузкой.

## Управление загрузкой и режимом USB

**BOOT/nRPIBOOT и OTG выполняют разные задачи.** BOOT принудительно включает ROM-загрузку CM4 по USB; OTG переключает шину USB CM4 между хост-разъёмами и сервисным портом прошивки. Переключайте их только при полностью обесточенной плате.

| Компоновка платы из #101 | Прошивка по USB | Штатная загрузка и клавиатура USB |
| --- | --- | --- |
| Фиолетовая `CM4_WiFi7 Rev1.0` без тумблера DEV/HOST | Замкните джампер **BOOT** и отдельную пару **OTG** (маркировка `OTG Short=Device`) | Разомкните джамперы **BOOT** и **OTG** |
| Зелёная `CM4_WIFI7_2409` с тумблером DEV/HOST | Замкните контакт **BOOT**, переведите переключатель **OTG → DEV** | Разомкните контакт **BOOT**, переведите переключатель **OTG → HOST** |

Определяйте контакты по шелкографии на плате. На плате без переключателя перенос единственного джампера с OTG на BOOT не активирует обе функции: для прошивки по USB требуются обе. Не замыкайте посторонние контакты GPIO под видом BOOT.

В [описании оборудования платы M4+](https://www.badgerwifi.co.uk/store/p/wlanpi-m4-plus) указано, что режим Device отключает порты USB-A. По этой причине подключение локальной клавиатуры и прошивка по USB используют разные схемы коммутации. При отличии ревизии платы следуйте документации производителя.

## Схема подключения для прошивки по USB

```text
Провижинер M4+ USB-A ── активный хаб ── кабель данных ── сервисный USB-C целевого M4+

Провижинер M4+ RJ45 ── изолированный коммутатор ── целевой M4+ RJ45
                                                  PoE отключено; питание через хаб
```

Установите перемычки BOOT/Device на целевой плате согласно таблице, затем следуйте инструкции [Прошивка CM4 через USB](../usb-provisioning.md). Модулю по-прежнему требуется Ethernet для DHCP, скрипта и образа. Отключите PoE на порту коммутатора только для целевого модуля; провижинер должен оставаться запитанным.

По окончании отключите кабель USB перед размыканием BOOT и возвратом в режим Host. Перезапуск по PoE не может обесточить плату, продолжающую получать питание по USB.

## Схема подключения для консоли tty2

```text
Провижинер M4+ RJ45 ── изолированный коммутатор ── целевой M4+ RJ45 / PoE
                                                   ├─ HDMI ── монитор
                                                   └─ USB-A ── проводная клавиатура
```

Разомкните BOOT и переведите плату в режим Host. Отключите кабель USB между устройствами, затем следуйте руководству [Локальная консоль целевого модуля](../local-console.md) при сетевой загрузке. Встроенный ЖК-экран M4+ не является консолью tty2 утилитарной ОС.

Настройка USB-гаджетов из обсуждения #101 относится к установленной операционной системе WLAN Pi OS. Процесс провижининга использует CM4 ROM и утилитарную ОС cmprovision; он не требует правки `/boot/config.txt` образа или установки Windows-драйверов RNDIS.
