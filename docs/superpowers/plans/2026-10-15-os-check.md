# The OS check after the first boot (2.6.0) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A project with "Check the OS after the first boot" reboots each module into its freshly written system on the stand. There a one-shot service installs the project's `.deb` packages, runs its first-boot scripts and reports the host name and the result. The run is done only after that report, and the label can print `$hostname`.

**Architecture:**
- The server renders the service, `resources/views/scriptexecute/firstboot.blade.php`, into the module's script.
- The module script's last post-install step, `resources/views/scriptexecute/oscheck-install.blade.php`, mounts the written root partition and puts the service there. The module then reports "written" and reboots.
- `ScriptExecuteController` keeps the run in a new phase `firstboot` until the report arrives (`?firstboot=1`). The run fails when the module comes back to network boot, or when `FirstBootTimeout` finds no report after 15 minutes.
- Packages are uploaded to `public/uploads/packages` (`AddPackageController`, `DebPackage`) and chosen in the project like scripts.

**Tech Stack:** Laravel 13 (Laravel 8 layout), Livewire 3, SQLite, POSIX sh (BusyBox ash in the utility OS, dash in the new system), systemd, apt, a static ARM helper written in C.

**Spec:** docs/superpowers/specs/2026-10-15-os-check-design.md

## Global Constraints

**Environment**
- PHP ≥ 8.3 (the bench runs 8.4), Laravel 13 with the Laravel 8 layout, Livewire 3. No new Composer or npm packages.
- The utility OS runs BusyBox 1.31 ash. The module script and the install step use only its applets: `mount`, `umount`, `cp`, `ln`, `mkdir`, `sync`, `reboot`, `sh`.
- The new system's `/bin/sh` (dash) runs the service with Debian tools: `systemctl`, `timeout`, `curl`, `apt-get`, `sha256sum`, `awk`, `tr`.

**Texts, verbatim from the spec**
- Phase label: «Checking the OS».
- Step name: «Installing the OS check».
- Log lines: «OS check skipped: the module booted over USB.» and «Image written. Rebooting into the new system to check it.».
- Failure reasons:
  - «The new system did not start: the module came back to network boot.»
  - «No report from the new system in 15 min»
  - «OS check failed: <reason>».
- Reasons from the service:
  - «first boot script '<name>' exited <code>»
  - «first boot script '<name>' timed out after <n> s»
  - «package <name>: download failed»
  - «package <name>: SHA256 mismatch»
  - «package install failed: apt-get exited <code>».

## Review Focus

1. **The new system reboots on its own before the service has finished** (an image that expands its root partition and restarts). The service runs again on the next boot and reports again. The server takes the first report and ignores a second one for a run that is no longer waiting. Task 7: `test_a_report_nobody_waits_for_is_ignored`.
2. **A first-boot log bigger than 1 MiB.** It is cut at `MAX_LOG_SIZE` with the usual note, not stored whole. Task 7: `test_a_log_bigger_than_the_limit_is_cut`.
3. **A project with the check but no packages and no first-boot scripts.** The service still reports the host name and the systemd state and passes. Task 5: `test_a_clean_first_boot_reports_and_shows_ready`.
4. **A first-boot script whose name holds quotes or spaces.** The name stays one shell word in the service and appears verbatim in the reason. Task 5: `test_a_script_name_with_quotes_stays_one_word`.
5. **A server the new system cannot reach** (403 from another network, server down). The service retries, then shows "fail" on the LEDs. The server fails the run after 15 minutes, and a late report still counts. Task 5: `test_a_report_that_never_arrives_shows_fail`. Task 7: `test_no_report_in_15_minutes_fails_the_run_and_a_late_one_still_counts`.

## Plan rulings against the spec

These are the plan's own decisions where it departs from the spec's wording; each also goes into the ledger.

- **The two enums become strings.** `scripts.script_type` and `projects.label_moment` keep their values and add `firstboot`, as the spec says, but as strings, so a later value needs no rebuilt table. The app validates the values. Cost if wrong: none for the user.
- **`ledpattern` is not moved to `/run`**, as the spec puts it, because `/run` can be mounted `noexec`. The service starts the helper from its own directory and removes the directory a second later; the running helper keeps its file open. Cost if wrong: where the helper cannot start, the kernel triggers show the result, as the spec allows.
- **Packages come by a plain form that reloads the Scripts page,** with no progress bar as the images have. Packages are small next to images. Cost if wrong: a large package uploads without a progress bar.
- **The label moment reads «After the OS check (with $hostname)»** in the form; the spec's name is «After the OS check».

```php
<?php

use Illuminate\Database\Migrations\Migration;
use Illuminate\Database\Schema\Blueprint;
use Illuminate\Support\Facades\DB;
use Illuminate\Support\Facades\Schema;

/* 2.6.0, the OS check after the first boot (docs/superpowers/specs/2026-10-15-os-check-design.md): the project's
   switch, a script type and a label moment for it, and what the module's new system reports.
   scripts.script_type and projects.label_moment were enums, a CHECK constraint in SQLite: they become strings (the app
   validates them), so a new value never again needs a rebuilt table. ->change() rebuilds both tables: Laravel switches
   the foreign keys off around the rebuild, which SQLite ignores inside a transaction, and dropping the old table would
   then delete the project_script rows and clear the project of every module and batch (cascades). So this migration
   runs outside a transaction. */
return new class extends Migration
{
    public $withinTransaction = false;

    public function up(): void
    {
        Schema::table('scripts', function (Blueprint $table) {
            $table->string('script_type', 20)->change();
        });
        Schema::table('projects', function (Blueprint $table) {
            $table->string('label_moment', 20)->change();
        });
        Schema::table('projects', function (Blueprint $table) {
            $table->boolean('os_check')->default(false);
        });
        Schema::table('cms', function (Blueprint $table) {
            // pending (checked once written), waiting (rebooted into the new system), passed, failed, skipped (USB boot)
            $table->string('os_check', 10)->nullable();
            $table->string('hostname', 64)->nullable();
            $table->string('os_state', 20)->nullable();
            $table->text('os_failed_units')->nullable();
            $table->timestamp('os_checked_at')->nullable();
            $table->text('os_check_output')->nullable();
        });
    }

    public function down(): void
    {
        Schema::table('cms', function (Blueprint $table) {
            $table->dropColumn(['os_check', 'hostname', 'os_state', 'os_failed_units', 'os_checked_at', 'os_check_output']);
        });
        Schema::table('projects', function (Blueprint $table) {
            $table->dropColumn('os_check');
        });
        // what 2.5 cannot hold: its label moment falls back to "after provisioning", its scripts go
        DB::table('projects')->where('label_moment', 'firstboot')->update(['label_moment' => 'postinstall']);
        DB::table('scripts')->where('script_type', 'firstboot')->delete();
        Schema::table('scripts', function (Blueprint $table) {
            $table->enum('script_type', ['postinstall', 'preinstall'])->change();
        });
        Schema::table('projects', function (Blueprint $table) {
            $table->enum('label_moment', ['never', 'preinstall', 'postinstall'])->change();
        });
    }
};
```

```php
<?php

namespace App\Services;

/* What a .deb says about itself (dpkg-deb --field): its package, version and architecture. A method of an instance
   from the container, so that a test can stand in for dpkg-deb. */
class DebPackage
{
    /** ['package' => ..., 'version' => ..., 'architecture' => ...], or null when dpkg-deb does not read the file */
    public function fields(string $path): ?array
    {
        $out = [];
        $code = 1;
        // several fields come back as "Field: value" lines
        @exec('dpkg-deb --field '.escapeshellarg($path).' Package Version Architecture 2>/dev/null', $out, $code);
        if ($code !== 0)
            return null;
        $fields = [];
        foreach ($out as $line)
            if (preg_match('/^(Package|Version|Architecture):\s*(\S.*)$/', $line, $m))
                $fields[strtolower($m[1])] = trim($m[2]);
        return isset($fields['package'], $fields['version'], $fields['architecture']) ? $fields : null;
    }
}
```

```php
<?php

namespace App\Http\Controllers;

use App\Models\Package;
use App\Services\DebPackage;
use Illuminate\Http\Request;
use Illuminate\Support\Str;

/* A .deb for the OS check (Scripts page, Packages) by a plain form, as the images come (Livewire handles large
   files badly); dpkg-deb tells what it is, the server keeps its SHA256 for the module to check */
class AddPackageController extends Controller
{
    public function store(Request $req, DebPackage $deb)
    {
        @set_time_limit(3600);
        $req->validate(['package' => 'required|file']);
        $file = $req->file('package');
        $name = $file->getClientOriginalName();
        if (strtolower($file->getClientOriginalExtension()) !== 'deb')
            return $this->back('Only .deb packages can be uploaded.');
        $fields = $deb->fields($file->getPathname());
        if (!$fields)
            return $this->back("'$name' is not a Debian package.");

        $package = new Package([
            'filename' => $name,
            'size' => $file->getSize(),
            'sha256' => hash_file('sha256', $file->getPathname()),
            'deb_package' => $fields['package'],
            'deb_version' => $fields['version'],
            'deb_architecture' => $fields['architecture'],
        ]);
        do {
            $package->filename_on_server = Str::random(40).'.deb';
        } while (file_exists($package->path()));
        $file->move(public_path('uploads/packages'), $package->filename_on_server);
        $package->save();

        return $this->back('Package '.$package->deb_package.' '.$package->deb_version.' ('.$package->deb_architecture.') added.');
    }

    protected function back(string $message)
    {
        session()->flash('message', $message);
        return redirect()->route('scripts');
    }
}
```

```blade
        i=$((i + 1))

        return 1

    rc=$?
    [ "$rc" -eq 0 ] || fail "package install failed: apt-get exited $rc"
fi
@endif

# 3. The project's first-boot scripts in its order, each with a time limit; the first failure stops them
run_script() {   # run_script <file> <name>
    [ "$RESULT" -eq 0 ] || return 0
    log "=== first boot script '$2'"
    timeout "$SCRIPT_SECONDS" sh -v "$1" >> "$LOG" 2>&1
    rc=$?
    if [ "$rc" -eq 124 ]; then
        fail "first boot script '$2' timed out after $SCRIPT_SECONDS s"
    elif [ "$rc" -ne 0 ]; then
        fail "first boot script '$2' exited $rc"
    fi

@endforeach

sent=no
i=0
while [ "$i" -lt "$TRIES" ]; do
    if curl -fsS --connect-timeout 10 --max-time 120 -F "log=@$LOG" --form-string "hostname=$HOST" \
            --form-string "state=$STATE" --form-string "failed_units=$FAILED" --form-string "reason=$REASON" \
            "http://$SERVER/scriptexecute?serial=$SERIAL&firstboot=1&retcode=$RESULT" > /dev/null 2>> "$LOG"; then
        sent=yes
        break
    fi
    i=$((i + 1))
    sleep "$PAUSE"
done
if [ "$sent" = no ]; then
    RESULT=1
    log "the report did not reach the server"
fi

# 6. Once only: the unit and its link go now, this directory once the helper runs; the log stays
rm -f "$WANTS" "$UNIT"

# 7. The result on the LEDs until the next boot: ready (both fade in and out together) or fail, by the helper the
#    utility OS had, else by kernel triggers

[ "$RESULT" -eq 0 ] || MODE=fail
if [ -x "$DIR/ledpattern" ] && "$DIR/ledpattern" check 2>/dev/null; then
    "$DIR/ledpattern" "$MODE" &
    LED_PID=$!
    sleep "$GRACE"   # the helper runs before its file goes
    rm -rf "$DIR"
    wait "$LED_PID"
    exit 0
fi
rm -rf "$DIR"
ACT=$LEDS/led0; [ -e "$LEDS/ACT" ] && ACT=$LEDS/ACT
PWR=$LEDS/led1; [ -e "$LEDS/PWR" ] && PWR=$LEDS/PWR
led() {   # led <led> none <0|1> | <trigger>
    [ -e "$1/trigger" ] || return 0
    echo "$2" > "$1/trigger"
    [ "$2" != none ] || echo "$3" > "$1/brightness"
}
if [ "$MODE" = ready ]; then
    led "$ACT" none 1
    led "$PWR" none 1
else
    led "$ACT" none 0
    led "$PWR" heartbeat
fi
exit 0
```

```php
<?php

namespace App\Jobs;

use App\Events\CmProvisioningFailed;
use App\Models\Cm;
use App\Models\Cmlog;
use App\Models\NotificationBatch;
use Illuminate\Bus\Queueable;
use Illuminate\Contracts\Queue\ShouldQueue;
use Illuminate\Foundation\Bus\Dispatchable;
use Illuminate\Queue\InteractsWithQueue;

/* The OS check (2.6.0): Cm::FIRSTBOOT_SECONDS after a module rebooted into its new system nothing has reported. Queued
   when the module reports its image written (ScriptExecuteController); a report that comes later still counts. A run
   started since, or one that has its report, is left alone. */
class FirstBootTimeout implements ShouldQueue
{
    use Dispatchable, InteractsWithQueue, Queueable;

    public $cmId, $runStartedAt;
    public $timeout = 80;   // under the database queue's retry_after (90 s)

    public function __construct(int $cmId, int $runStartedAt)
    {
        $this->cmId = $cmId;
        $this->runStartedAt = $runStartedAt;
        $this->onQueue('boards');
    }

    public function handle(): void
    {
        $cm = Cm::find($this->cmId);
        if (!$cm || $cm->phase !== 'firstboot' || !$cm->provisioning_started_at
            || $cm->provisioning_started_at->getTimestamp() !== $this->runStartedAt)
            return;
        // early: only the tests' sync queue runs a delayed job at once
        if ($cm->phase_started_at && $cm->phase_started_at->getTimestamp() + Cm::FIRSTBOOT_SECONDS > now()->getTimestamp())
            return;

        $cm->os_check = 'failed';
        $cm->markFailed(Cm::OS_NO_REPORT)->save();
        Cmlog::create(['cm' => $cm->serial, 'board' => $cm->provisioning_board, 'loglevel' => 'error',
            'msg' => Cm::OS_NO_REPORT.': the new system did not start, has no network to the server, or the module was unplugged.']);
        if ($cm->notification_batch_id)
            NotificationBatch::whereKey($cm->notification_batch_id)->update(['last_event_at' => now()]);
        CmProvisioningFailed::dispatch($cm);
    }
}
```

```php
    /* The image is written and the OS check is due: the module reboots into its new system, whose service reports
       (registerFirstBoot()); FirstBootTimeout fails the run when nothing comes. A label "after writing" prints now. */
    protected function rebootIntoTheNewSystem(Request $req, $project)
    {
        $this->cm->temp2 = $req->query('temp');
        $this->cm->os_check = 'waiting';
        $this->cm->setPhase('firstboot');
        $this->cm->save();
        $this->touchBatch();

        $msg = 'Image written.';
        if ($req->query('verify'))
            $msg .= ' Verification successful.';
        $printLabel = $project && $project->label_moment == 'postinstall' && $project->label;
        if ($printLabel)
            $msg .= ' Printing label.';
        $this->logInfo($msg.' Rebooting into the new system to check it.');
        if ($printLabel)
            $this->printLabel();

        try
        {
            FirstBootTimeout::dispatch($this->cm->id, $this->cm->provisioning_started_at->getTimestamp())
                ->delay(now()->addSeconds(Cm::FIRSTBOOT_SECONDS));
        }
        catch (\Throwable $e)
        {
            report($e);   // the run waits until the module reports or comes back
        }
        return '';
    }

    /* ?firstboot=1: the OS check's report from the new system (resources/views/scriptexecute/firstboot.blade.php) with
       its log, host name, systemd state and failed units; retcode 0 passes the check. A report nobody waits for (the
       service ran again after a reboot of its own) changes nothing. */
    public function registerFirstBoot(Request $req)
    {
        $this->cm = Cm::where('serial', $this->serial)->first();
        if (!$this->cm || !$this->cm->awaitsOsReport())
            return '';

        $log = $req->hasFile('log') ? $req->file('log')->get() : '';
        if (strlen($log) > self::MAX_LOG_SIZE)
            $log = substr($log, 0, self::MAX_LOG_SIZE)."\nLog was bigger than max allowed size. Truncated.";
        $host = substr(preg_replace('/[^A-Za-z0-9.-]/', '', (string) $req->input('hostname')), 0, 64);
        $state = substr(preg_replace('/[^a-z-]/', '', (string) $req->input('state')), 0, 20);
        $units = trim(preg_replace('/\s+/', ' ', (string) $req->input('failed_units')));
        $this->cm->hostname = $host !== '' ? $host : null;
        $this->cm->os_state = $state !== '' ? $state : null;
        $this->cm->os_failed_units = $units !== '' ? Str::limit($units, 2000, '') : null;
        $this->cm->os_checked_at = now();
        $this->cm->os_check_output = $log;

        if ((string) $req->query('retcode') === '0')
        {
            $this->cm->os_check = 'passed';
            $this->cm->provisioning_complete_at = now();
            $this->cm->setPhase('done');
            $this->cm->save();
            $this->touchBatch();
            $project = $this->cm->project;
            $printLabel = $project && $project->label_moment === 'firstboot' && $project->label;
            $this->logInfo('OS check passed'.$this->osAbout().'.'.($printLabel ? ' Printing label.' : '')."\n\n".$log);
            if ($printLabel)
            {
                try
                {
                    PrintLabel::dispatch($this->cm->id);   // the report does not wait for the printer
                }
                catch (\Throwable $e)
                {
                    report($e);
                }
            }
            CmProvisioningComplete::dispatch($this->cm);
            return '';
        }

        $reason = Str::limit(trim((string) $req->input('reason')), 200, '');
        $msg = 'OS check failed: '.($reason !== '' ? $reason : 'the new system reported a failure');
        $this->cm->os_check = 'failed';
        $this->logInfo($msg.$this->osAbout().".\n\n".$log, 'error');
        $this->cm->markFailed($msg)->save();
        $this->failed();
        return '';
    }

    /* " on wlanpi-a1b (systemd: degraded; failed: firefox-setup.service)" for the log */
    protected function osAbout()
    {
        $about = $this->cm->hostname ? ' on '.$this->cm->hostname : '';
        $parts = [];
        if ($this->cm->os_state)
            $parts[] = 'systemd: '.$this->cm->os_state;
        if ($this->cm->os_failed_units)
            $parts[] = 'failed: '.$this->cm->os_failed_units;
        return $about.($parts ? ' ('.implode('; ', $parts).')' : '');
    }
```

```markdown
## The OS check after the first boot ##

A project with **Check the OS after the first boot** does not stop when the image is written. The module reboots into its new system right on the stand, where a one-shot service checks it:

1. After the post-install scripts the utility OS mounts the written root partition (the image's second partition, ext4) and adds the service `cmprovision-firstboot`, with the project's first-boot scripts and packages.
1. The module reboots. Its bootloader must try eMMC before the network (`BOOT_ORDER`, e.g. `0xf21`); otherwise the module comes back to network boot and the run fails with "the new system did not start".
1. The new system gets its address from the stand's DHCP and waits for its boot to finish (at most 5 minutes). Then it installs the project's packages with one `apt-get` and runs the first-boot scripts, 2 minutes each; a non-zero exit fails the check.
1. It reports its host name, the systemd state and the failed units. The service then removes itself; its log stays in `/var/log/cmprovision-firstboot.log`.
1. Only now is the run done. The label can print `$hostname` (label moment "After the OS check"), and the notifications go out. Without a report in 15 minutes the run fails.
1. The module keeps running and shows the result on its LEDs: ACT and PWR fade in and out together when the check passed, the error pattern when it failed.

- **First-boot scripts** are a script type of their own (Scripts → first boot): they run as root in the new system, with `$SERVER` set.
- **Packages** (Scripts → Packages) are `.deb` files uploaded to the server. The stand has no internet, so apt downloads nothing: whatever a package depends on must be in the image or be uploaded too.
- Anyone who reaches the provisioner's web server can download the files under `/uploads`, the images included: keep secrets out of packages.
- The new system needs systemd and curl. A module booted over USB (rpiboot) is not checked: a reboot would bring it back to USB boot.
```

```sh
    printf '%s: %s\n' "$s" "$(systemctl is-active $s || true)"
done
after=$(counts)
```
