# Сохранённые учётки для re-provision — 2.6.3~dev2

По запросу пользователя добавлен редактируемый список Settings → Re-provision accounts. После ключа провижинера Check access пробует включённые учётки по порядку; ручной ввод появляется, если они не дали доступ. Стирание остаётся отдельным подтверждённым действием.

## Реализация

- `SavedAccounts`: до 10 профилей, до 3 включённых; добавление, редактирование, включение/выключение, удаление, порядок. Начальные профили: WLAN Pi `wlanpi/wlanpi` включён, Raspberry Pi OS legacy `pi/raspberry` выключен.
- Полный список зашифрован через Crypt в `settings.reprovision_accounts`. APP_KEY и база уже входят в штатный backup/restore. Пустой список сохраняется пустым; повреждённые данные не заменяются молча заводскими профилями.
- Livewire-компонент получает только id, название, логин и enabled. Пароль живёт в Alpine и передаётся аргументом, пустой пароль при редактировании сохраняет прежний. Изменения требуют подтверждённого пароля веб-аккаунта.
- Автоматические попытки — один раз при создании операции и не чаще раза в минуту на serial, с общей для операторов отметкой в cache. Одинаковые login/password проверяются один раз. Явно введённая учётка не запускает предварительный перебор.
- После входа проверяются serial, носитель и sudo. Смена SSH host key, сетевой сбой или чужая идентичность прекращают автоматические попытки. Не подошедшая учётка/отсутствие sudo разрешают следующий профиль.
- Подошедший пароль попадает в прежний зашифрованный cache на 120 секунд для подтверждения wipe. Просроченный пароль сразу открывает смену, не запрашивая старый пароль снова. Новый пароль отдельного сенсора не перезаписывает общий профиль.
- `confirms-password` теперь создаёт отдельное окно и идентификаторы событий для каждого Livewire-компонента. Это сохраняет независимость форм сохранённых учёток и Wi-Fi на одной странице Settings.
