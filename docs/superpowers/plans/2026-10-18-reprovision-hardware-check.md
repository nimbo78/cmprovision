# Re-provision: аппаратная проверка 18 октября 2026

Пакет: `cmprovision4 2.6.3~dev1`. Проверка выполняется через настоящий интерфейс Livewire в Edge/Playwright, без подмены SSH. Все времена ниже — UTC.

## Стенд и цель

- Провижинер: `wlanpi-da2`, WLAN Pi M4+, Raspberry Pi OS Trixie, PHP 8.4.
- Тестовый сенсор: `sensor1`, hostname `wlanpi-059`, serial `100000004acecfa4`.
- MAC `2c:cf:67:30:60:59`, DHCP `172.20.157.173`, коммутатор `t-iof-sw01-provision`, порт `Gi0/5`.
- eMMC `/dev/mmcblk0`, CID `150100424a5444345203e758c0d3ca00`, 61 071 360 секторов. Агент подтвердил MBR и ext4 root на втором разделе.
- Активный проект `stage1-test`, образ `wlanpi-os-26.10-DeadEye-full.img.gz`, 6 211 764 224 байта после распаковки; SHA256-проверка и OS check включены, split image выключен.
- В проекте включена установка агента для последующих запусков. Другие сенсоры не перезапускаются.

## Обновление провижинера

До установки активных прошивок не было. Снимок версии 2.6.2: `/var/backups/cmprovision/20261018-184416-2.6.2`, включая согласованную копию SQLite и переустанавливаемый пакет.

Первая сборка из рабочего дерева Windows потеряла execute bit у `artisan`; post-install остановился до миграции. Права исправлены, настройка пакета завершена. В `debian/rules` закреплены права 0755, а упаковка рабочего дерева учитывает режимы Git. Исправленная сборка прошла повторную установку; `dpkg --audit` пуст, nginx, PHP-FPM, dnsmasq и обе очереди работают.

SHA256 исправленного пакета: `0276623e3442eddc5e4edeebcb14dfbbd19774647941b23249d0b2f6b318f9a4`.

Ключ создан на настоящем провижинере: private 0600, public 0644, владелец `www-data`; тестовые ключи в пакет не входят.

Штатный бэкап новой версии: `/var/backups/cmprovision/20261018-190016-2.6.3~dev1`. На самом провижинере проверены совпадение private/public key и `.env` с живыми файлами, права private key 0600 и каталога бэкапа 0700, `PRAGMA quick_check=ok` для копии SQLite и наличие переустанавливаемого пакета. Секреты на ПК не копировались. Восстановление поверх работающего стенда не выполнялось.

## Первый проход: установленная ОС без агента

- Проверка ключа предложила учётку сенсора; вход через `wlanpi` и проверка sudo прошли.
- В диалоге сверены serial, IP, hostname, диск и CID. Подтверждение вызвано штатной кнопкой **Wipe and re-provision**.
- `15:50:51`: сервер получил подтверждение стирания, операция перешла в `waiting`.
- `15:51:25`: тот же сенсор запросил новый provisioning; операция стала `booted`, запись образа началась с нуля. Ручной PoE restart не потребовался.
- `15:56:33`: SHA256 совпал, установка агента завершилась сообщением `agent installed`, началась загрузка установленной ОС.
- `15:58:00`: OS check прошёл на `wlanpi-059`, systemd `running`, failed units нет. Тестовый пакет и оба first-boot скрипта выполнены. Полный прогон занял 6:35.
- Во время записи и OS check повторная перепрошивка блокировалась. Ошибок JavaScript в настоящем диалоге не было.

## Проверка ограниченного ключа

После первого прогона установленный ключ вернул ожидаемую идентичность через `identify`. Попытка выполнить `id` получила `refused: unknown command`; запрос с заведомо неверным нулевым serial получил `refused: serial 100000004acecfa4`, без стирания и перезагрузки.

## Второй проход: ключ провижинера

- Настоящий диалог показал `Access over the provisioner's key. Serial matches.`; пароль сенсора не использовался.
- `15:59:42`: подтверждён wipe по ключу.
- `16:00:16`: сенсор вернулся в сетевую загрузку, операция стала `booted`, начался второй прогон с нуля. Ручной PoE restart снова не потребовался.

- `16:05:24`: SHA256 совпал, агент снова установлен, началась проверка установленной ОС.
- `16:06:51`: OS check прошёл, systemd `running`, failed units нет. Второй полный прогон также занял 6:35.
- После второго прогона повторно проверены `identify` по ключу, отказ посторонней команды и неверного serial. Идентичность сенсора и носителя не изменилась.

Оба полных цикла завершились без ручного перезапуска и ошибок JavaScript. Настоящие wipe отправлялись только кнопкой приложения после повторной проверки цели и подтверждения. Провижинер остался на `2.6.3~dev1`; в `stage1-test` оставлена включённой установка агента. Временная веб-сессия проверки удалена, незавершённые проверки доступа отменены.

## Границы проверки

Этот стенд проверяет конкретный CM4 с eMMC, MBR и `BOOT_ORDER=0xf21`. Результат не распространяется на GPT, USB/NVMe или другой порядок загрузки. Просроченный пароль и split/resume проверялись отдельно в автоматических тестах; здесь они пока не воспроизводились.
