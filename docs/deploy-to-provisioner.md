# Выкладка на провижинер

Как обновить код на рабочем провижинере `wlanpi-da2` (стили, логотип, новая
функция, исправление) — до пуша в GitHub или вместо него. Это ручной флоу для
проверки на живом железе: пушим мы только после того, как пакет собрался и
встал на провижинере.

Пакет `cmprovision4` — `Architecture: all` (чистый PHP плюс заранее собранный
ARM-бинарник `ledpattern`, он уходит в пакет как есть), поэтому собирается прямо
на провижинере. Схема: передать рабочее дерево на da2 → собрать там `.deb` →
поставить его → `postinst` накатит миграции и перезапустит PHP-FPM.

Кросс-ссылки: сеть провижинера — [provisioner-network.md](provisioner-network.md);
про саму сборку `.deb` и про `vendor/` — в корневом `CLAUDE.md`.

## Где запускать команды

Подходят обе оболочки Windows 11, равноправно — **Git Bash** (ставится с Git для
Windows) и **PowerShell** (встроенный Windows PowerShell 5.1). В VS Code любая
открывается стрелкой рядом с «+» в панели терминала; обе читают один и тот же
`C:\Users\igors\.ssh\config`, поэтому `ssh da2` работает в каждой.

Почти все команды ниже **одинаковы в обеих оболочках**: тяжёлая часть идёт на
провижинере внутри одинарных кавычек (`ssh da2 '…'`), а локальная оболочка её не
трогает. Отличается только одна команда — труба `git archive | ssh` в шаге 1, — и для
неё в шаге 1 дан отдельный блок под каждую оболочку.

Две особенности PowerShell 5.1, уже учтённые в доке (проверены на этом ПК):
- **Труба портит архив.** PowerShell 5.1 гонит поток между программами как текст и
  перекодирует байты (архив в 18 МБ пришёл с другим хешем). Поэтому трубу в шаге 1
  запускаем через `cmd /c "…"` — у cmd трубы байтовые.
- **Двойные кавычки внутри `ssh da2 '…'` теряются** — поэтому удалённые команды
  написаны без внутренних двойных кавычек и работают в обеих оболочках одинаково.

WSL для этого не нужен: это отдельный Linux со своим домашним каталогом — без вашего
ключа SSH, `known_hosts` и настроек, а репозиторий виден ему только через `/mnt/c`.

## Один раз: псевдоним `da2`

Адрес, пользователь и псевдоним ключа хоста лежат в `C:\Users\igors\.ssh\config` —
этот файл читают оба клиента SSH (Git Bash и Windows):

```
Host da2
    HostName 192.168.68.237
    User claude
    HostKeyAlias 192.168.25.30
```

- `HostName` — адрес провижинера по Wi-Fi. Его раздаёт DHCP, и он уже менялся
  (`192.168.25.30` → `192.168.68.237`): если `ssh da2` перестал подключаться, узнайте
  новый адрес и поправьте эту строку.
- `User claude` — вход по ключу (`~/.ssh/id_ed25519`), sudo без пароля. У пользователя
  `wlanpi` sudo просит пароль: тогда команды с `sudo` запускайте как `ssh -t da2 '…'`.
- `HostKeyAlias` — ключ хоста записан в `known_hosts` под старым адресом.

Проверка (из любой оболочки):

```sh
ssh da2 'hostname; dpkg-query -W cmprovision4'
```

Ответ — `wlanpi-da2` и установленная версия пакета.

Каталог сборки на провижинере — `~/cmprovision/build/cmprovision`.

## 1. Отправить рабочее дерево

`git archive` упаковывает закоммиченный `HEAD` — без `.git`, без неотслеживаемых
файлов, без `vendor/`. Сначала очищаем каталог сборки, чтобы удалённые вами файлы не
остались и не попали в пакет. Запускайте из корня репозитория: терминал VS Code
обычно открывается там сам, а блоки ниже начинаются с `cd` на всякий случай. Если
`git archive` ругается `not a git repository` — вы не в том каталоге.

Git Bash:

```sh
cd "/c/Users/igors/OneDrive/Документы/Claude/cmprovision"
ssh da2 'rm -rf ~/cmprovision/build/cmprovision && mkdir -p ~/cmprovision/build/cmprovision'
git archive HEAD | ssh da2 'tar -x -C ~/cmprovision/build/cmprovision'
```

PowerShell (Windows 11; труба — через `cmd /c`):

```powershell
cd "C:\Users\igors\OneDrive\Документы\Claude\cmprovision"
ssh da2 'rm -rf ~/cmprovision/build/cmprovision && mkdir -p ~/cmprovision/build/cmprovision'
cmd /c "git archive HEAD | ssh da2 tar -x -C ~/cmprovision/build/cmprovision"
```

**Сначала закоммитьте.** `git archive HEAD` берёт `HEAD`, а не несохранённые правки.
Для проверки сгодится черновой коммит — потом его можно поправить
(`git commit --amend`) или снять (`git reset`).

## 2. Собрать `.deb` на провижинере

```sh
ssh da2 'cd ~/cmprovision/build/cmprovision && dpkg-buildpackage -b -us -uc -d'
```

- `-b` — только бинарный пакет, `-us -uc` — без подписи, `-d` — пропустить проверку
  сборочных зависимостей (на da2 есть debhelper и composer, но нет метапакета
  `build-essential`).
- Сборка выполняет `composer install --optimize-autoloader --no-dev` (цель `vendor`
  в корневом `Makefile`) и занимает ~2,5 минуты.
- `.deb` кладётся на уровень выше: `~/cmprovision/build/cmprovision4_<версия>_all.deb`
  (версия — верхняя строка `debian/changelog`). Каталог сборки шаг 1 очищает, а
  собранные пакеты остаются — пригодятся для отката.

## 3. Установить

```sh
ssh da2 'sudo dpkg -i $(ls -t ~/cmprovision/build/*.deb | head -1)'
```

`ls -t … | head -1` берёт самый свежий `.deb`. `postinst` сам выполнит
`php artisan migrate --force`, поправит владельцев, перепишет пул FPM и перезапустит
PHP-FPM; службы очереди перезапустит `dh_installsystemd`. Если dpkg пожалуется на
зависимости (на машине, где пакет уже работает, не должен) —
`ssh da2 'sudo apt-get -f install'`.

### Ловушка одинаковой версии

debhelper ставит всем файлам пакета mtime из даты записи changelog. Поставьте **ту
же** версию второй раз — opcache PHP не заметит изменённый код, а dpkg может не
счесть это обновлением (и не перезапустит FPM). Два выхода:

- **Менять версию на каждую сборку** (чисто): для теста достаточно поправить номер в
  верхней строке `debian/changelog`, например `(2.6.0)` → `(2.6.0+test1)`, и
  закоммитить — `git archive` берёт только коммит. Для настоящего релиза — новая
  запись сверху.
- **Либо перезапустить вручную** после установки той же версии:

```sh
ssh da2 'sudo systemctl restart php8.4-fpm cmprovision-queue cmprovision-queue-images'
```

## 4. Проверить

- Открыть веб-интерфейс провижинера и глянуть **Settings → Status**: два
  воркера очереди и dnsmasq должны быть зелёными.
- Версия: `ssh da2 'dpkg-query -W cmprovision4'`.
- Журнал, последние 50 строк:
  `ssh da2 'sudo journalctl -u php8.4-fpm -u cmprovision-queue -n 50 --no-pager'`.

## 5. Откат

Собранные пакеты, свежие сверху:

```sh
ssh da2 'ls -t ~/cmprovision/build/*.deb'
```

Вернуться на нужный (подставьте файл из списка):

```sh
ssh da2 'sudo apt-get install --reinstall --allow-downgrades ~/cmprovision/build/cmprovision4_2.6.0_all.deb'
```

Это откат **кода**: миграции базы, которые успела выполнить новая версия, остаются.
Откат **данных** (база, прошивки, `.env`) — отдельно, через `cmprovision-restore` из
снимка; см. `CLAUDE.md`.

## Чистка после установки

Каждая сборка оставляет на da2 дерево исходников и сборочный каталог (около 0,4–0,6 ГБ), плюс присланный архив
(около 125 МБ); eMMC провижинера всего 29 ГБ, а на ней лежат образы (по 1–2 ГБ) и снимки бэкапов. Когда пакет
поставлен и проверен, уберите дерево и архив, а `.deb` оставьте — они нужны для отката:

```sh
ssh da2 'rm -rf ~/cmprovision/build/cmprovision ~/cmprovision/*.tar; df -h / | tail -1'
```

Каталоги вида `build/<имя>-<коммит>/` (если собирали в отдельном каталоге) делают то же: перед удалением перенесите
оттуда выпущенные `.deb` на уровень выше (`mv -n build/<каталог>/cmprovision4_<версия>_all.deb build/`). 22 октября 2026
такая чистка вернула 10 ГБ (свободно было 5,0, стало 15 ГБ).

## 6. Когда всё хорошо — пуш

Сборка на провижинере намеренно идёт до пуша: сначала пакет доказан на живом
железе. После успешной проверки:

```sh
git push origin <ветка>
```

и тег релиза — по обычному порядку.
